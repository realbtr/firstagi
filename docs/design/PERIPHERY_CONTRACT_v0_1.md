# K1 · Контракт периферии v0.1

Предложение к ревью, 10 ноября 2026, З-0123. [Принцип](../PRINCIPLE.md) ·
[Аудит кода](../../experiments/reports/principle_audit_2026-11.md).
Минимальный драйвер операционализирует положения 1, 3, 4 и 6, создаёт условия
для проверки 2 и 7 и один базовый способ встраивания по 9–10. Освоение
замыкания, интерес, охлаждение и развитие брокера остаются вопросами к ядру.

## Отчёт и команды

- Отчёт выдаёт упорядоченные переходы. Каждый успешный переход содержит
  исполненную команду, исходный ключ, целевой ключ, происхождение
  `reflex` / `program` и монотонную ревизию. Ключи и команды непрозрачны.
  Драйвер держит граф и включение областей. Публичная граница выдаёт
  только текущее наблюдение, запросы, квитанции и отчёт.
- Запрос программы указывает очередную команду и ожидаемое наблюдение
  (ключ + ревизия). Доступны обычный переход, запрос обратного перехода
  и запрос перехода во вложенную область. Обратный запрос называет
  намерение, фактически исполненную команду выбирает драйвер.
- Минимальный брокер использует фиксированный порядок запросов. Драйвер
  объявляет место для одной дополнительной команды перед очередным рефлексом
  на двух тактах из трёх. Брокер подаёт программу по одному шагу на такт.
  Каждое исполнение заново проверяет ключ и ревизию. Следующая команда
  планируется по свежему отчёту, включая рефлекторные переходы.
- Квитанция программы различает `executed`, `no_slot`, `stale` и `refused`.
  При отсутствии места проверка команды откладывается на решение вызывающего.
  При отказе запрос принят, но недоступен соответствующий переход.
  При устаревании ревизии программа пропускается. Рефлекс продолжается во
  всех случаях. Неуспешная команда не создаёт переход и не обновляет p/n.
- Обратный запрос восстанавливает исходное состояние последнего обратимого
  перехода, пока это его актуальная цель. Он даёт новую ревизию. Физическое
  совпадение ключа после возврата не делает старое предложение свежим.

## Минимальный генератор

Три места с двумя скрытыми источниками каждое. В каждом месте источники
дают общий грубый A, но имеют свои вложенные ключи. Один общий непрозрачный
код команды движения ведёт из A в B. В однозначном месте оба источника дают
один публичный B. В двух других — разные B. В первом из них вложенная
область раскрывается по запросу и различает источники, во втором драйвер
возвращает одинаковый отказ для обоих. В однозначном месте запрос доступен,
чтобы сравнение цены включало избыточное уточнение. Скрытые исходы при
отказе доступны оценщику через наблюдение после команды, вложенные ключи
остаются недоступны даже контролю максимального разрешения.

Генератор переставляет шесть случаев и даёт идентификаторы одного формата
из своего входа. Ключи совпадают в пределах грубого класса, меняются
после перехода и сохраняют равенство при возврате в ту же область.
Перестановка, признаки места и скрытый граф остаются внутри периферии
или тестового оценщика. У режимов одинаковые публичные меню до запроса.
Фиксированное движение рефлекса даёт замкнутые траектории для проверки
доставки. Оно не выбирает интересную область по результатам learner.
Граница v0.1 — вырожденная топология. Шесть случаев представлены отдельными
экземплярами с двумя физическими фазами и локальным вложением ключа A.
Внимание между местами в этом генераторе не перемещается.

## R1 · Ожидаемый результат по построению

Две сбалансированные проверочные пробы на место после одинакового покрытия.
Одинаковый публичный префикс до запроса, скрытая ветвь не выводится из порядка.
Числитель качества — верные прогнозы цели команды движения. Abstain
считается отдельно и остаётся в знаменателе. Цена — число попыток запроса
разрешения на пробу, включая отказ. Оценка относится к отображению
«доступный ключ и команда → цель». Дополнительная различающая история
меняет постановку. Таблицы получают только те ключи, которые может вернуть
драйвер, и учатся по тем же наблюдаемым исходам.

| Место | Грубая таблица: качество / цена | Максимальная таблица: качество / цена | Действующее ядро, запрос отключён | Действующее ядро, запрос доступен |
|---|---|---|---|---|
| Однозначное | 2/2, 0 | 2/2, 1 | 0 прогнозов действия, 0 запросов | 0 прогнозов действия, 0 запросов |
| Различимое вложением | ≤1/2, 0 | 2/2, 1 при покрытии обоих вложенных ключей | 0 прогнозов действия, 0 запросов | 0 прогнозов действия, 0 запросов |
| Вложение недоступно | ≤1/2, 0 | ≤1/2, 1 с отказом | 0 прогнозов действия, 0 запросов | 0 прогнозов действия, 0 запросов |
| Замыкание | Наблюдаемые циклы доступны в тех же отчётах | Те же циклы | 0 самостоятельных возвратов | 0 самостоятельных возвратов. Драйвер замыкает 6/6 ветвей при своевременном внешнем обратном запросе |

Прогноз для действующего ядра относится к токенному входу K1. У него нет
проводки от несовпадения к команде разрешения или возврата, поэтому полезных
прогнозов действия в знаменателе нет. Если считать отсутствие прогноза
воздержанием, это 0/2 попаданий в каждой паре проб. Это оценка способности
предложить действие, а не сравнение точности двух обученных предикторов.
На потоке из двух чередующихся точных признаков с пустой базой первый токен
завершает атом. Каждый следующий несовпадающий токен активирует новый атом
с ожиданием этого же признака, тогда как следующим придёт противоположный.
Из кода следуют один COMPLETED, 23 REFUTED, 24 Gen и 0 повторно укреплённых
Gen за 24 такта. [Загрузка контекста](../../core/algorithm.py#L170) ·
[Несовпадение](../../core/algorithm.py#L268)

Два разных внутренних A могут иметь один публичный ключ. Для 6/6
проверяющий сверяет внутреннее состояние с исходным и обе границы переходов.
В smoke счётчик публично замкнутых пар рефлексов описывает поток драйвера.
Число этих пар не измеряет самостоятельный выбор возврата.

## Совместимость и smoke

A1–A3, N3a, N5a–N5d и случаи PR36 сохраняются. Для smoke адаптер кодирует
только публичную тройку как `Feature`, создаёт уникальный token ID
на доставку и передаёт его существующему `LearningSystem.process_token`.
Одинаковые тройки получают одинаковый вектор, разные — различимые векторы.
Кодирование использует публичный отчёт без скрытой топологии, меток или готовых целей
входной задачи. Проекция служит подаче наблюдений, actual receipts A1 не
создаются. `success_count > 1` описывает повторное подтверждение токенных
обобщений. Сохраняются число переходов, публично замкнутые пары,
посещения по измерителю GenBase на шаг и размер сериализации ядра.

Фиксированный порядок и окно вставки — исходные варианты брокера.
Будущий контроль может упорядочивать те же точки по цене перемещения и
приоритету ядра при равном доступе. Нынешний ContextBroker отвечает за
поиск и доставку наблюдений, поэтому первые физические окна задаёт
драйвер K1. Изменение инвариантов поддержки или необходимость правки
`core/` для подключения — остановка и предмет отдельного ревью.
