## Допущения и счётчики

Одна O; затем тот же заранее заданный блок для каждой из m операций меню.
Публичная схема: channel/роль C4, непрозрачная O, опора x, местность t,
посторонний n. Все x различны; роль/O постоянны внутри блока. G — наблюдённое
относительное продолжение от замороженного x; +1/-1 ниже — разные классы
исхода, не подсказка эффекта O. Связь O→G извлекается только из actual.
В curriculum наблюдения полные; цель и принадлежность train/closed не входят
в K. Learner получает все публичные признаки без маски релевантности.

o — число origin (ровно один), pf — последующие positive frozen forecasts,
nneg — отрицательные. Здесь p=o+pf. Единое N3a: p≥2 и p/(p+nneg)>0.5,
плюс обычные A3/availability условия. Нет отдельного pf≥2 для connecting.
При o=1,nneg=0 первый последующий positive forecast даёт p=2 и допуск.
Origin считается positive actual, **не прогнозом**. Разделение o/pf — аудит.

W2: origin — событие, вызвавшее создание носителя: второе событие пары
или actual расширения. Первое событие пары служит построению K и не даёт
новому носителю p/n. Прогноз этого носителя возможен только в последующих
исполнениях при уже распознанном K, с замораживанием до actual.
Общий/уточнённый connecting не получает p/n старых носителей.

Индекс консолидации рассматривает все совместимые K этого малого блока;
порядок инкрементальный, не полный квадратичный scan. Если лимиты manifest
обрывают нужное сравнение, расчёт неприменим: NOT_READY, не бесплатный поиск.
Все arms получают одинаковые curriculum, операции, receipts и расписание.
Ни один вывод ниже не означает, что неизменённый текущий learner уже это умеет.

## Однородный блок: четыре actual на O

t=a всегда, G=+1; x меняется на каждом шаге.

| Actual | n | Состояние после actual | o / pf / nneg нужного носителя |
|---|---|---|---|
| 1 | 0 | Непарное исполнение для построения K | — |
| 2 | 0 | K0: t=a,n=0; x переменная; новый connecting0, origin=actual2 | 1/0/0 |
| 3 | 1 | K0 reject; расширение K1: t=a,n=?n; connecting1, origin=actual3 | 1/0/0 |
| 4 | 2 | K1 match; первый positive frozen forecast, p=2, допуск | 1/1/0 |

K1 распознаёт новые x/n, но не невиданную t. Однородный closed сохраняет
t=a и использует ранее не встречавшиеся x/n. Следующий n не создаёт редакцию
K1: переменная уже распознаёт его. Узкий connecting0 совместим по G, но его
evidence не суммируется с connecting1. Допуск нужной общности — после actual4.

## Неоднородный блок: восемь actual на O

G=+1 при t=a и G=-1 при t=b; n причинно не влияет.
Блок a — actual1–4 выше. Затем:

| Actual | t,n | Состояние после actual | o / pf / nneg нужного носителя |
|---|---|---|---|
| 5 | b,0 | K(a) reject; непарное исполнение для G=-1 | — |
| 6 | b,0 | Kb0: t=b,n=0; новый connecting, origin=actual6 | 1/0/0 |
| 7 | b,1 | Kb0 reject; расширение Kb1: t=b,n=?n, origin=actual7 | 1/0/0 |
| 8 | b,2 | Kb1 match; первый positive frozen forecast, p=2, допуск | 1/1/0 |

K(a) допускается после actual4, K(b) — после actual8. Разные G не объединяются
в один ключ. Этот блок проверяет создание/расширение, а не обнаружение
скрытого разделителя: конфликтное уточнение и G1 требуют отдельных
acceptance cases/curriculum. В closed новые x/n, но обе обученные t.
Перенос на новую причинно значимую t не предсказывается. Между O evidence
не заимствуется; пустой K в первом варианте не создаётся вообще.

## W3: явные ключи табличных arms

Таблицы предсказывают последствие O. В этой схеме фиксируются ключи:

| Arm | Ключ | Данный заранее prior / что неизвестно в closed |
|---|---|---|
| Полный контекст | (channel, cue-role, O, x, t, n) | x тоже публичен; новые x гарантируют неизвестный ключ по построению |
| Промежуточный контекст | (channel, cue-role, O, t, n) | «x не влияет» дан заранее; новые n делают ключ неизвестным |
| Сильная таблица | (channel, cue-role, O, t) | Правильное разрешение t дано; при покрытии t/O ожидается паритет точности |

Скрытые эффекты/правильная команда не передаются ни одной таблице; все
последствия обучаются по actual. G* используется при одинаковом для arms
выборе по прогнозам, а не как ключ forward-таблицы. Receipt/seq/время —
транспорт, для всех одинаково отделённый от контекста задачи. При добавлении
публичных cue-признаков полный ключ расширяется явно; их нельзя молча отбросить.
Протокол определит fallback/abstain и denominator неизвестных ключей.
Включение x в полный контроль — заявленное ограничение, не новая находка.

## Вывод R1 и бюджет до протокола

Для этих блоков: **4 actual/O** в однородном случае, **8 actual/O** для двух
местностей. Для m операций нижняя граница curriculum — **4m / 8m actual**;
для четырёх операций это16/32 (арифметика, не результаты опыта).
Расчёт включает только указанные блоки, без G1/конфликтного уточнения/closed.
Он не задаёт полный бюджет гейта и не переносит лимиты исторического v2.
При меньшем бюджете или неполном покрытии индекса — NOT_READY; ослаблять
единое N3a или продлевать серию по успеху нельзя. Реальное отставание K
фиксируется как отказ допуска в данном бюджете.

Отдельные сравнения: exact/native без общего K; три таблицы выше; native K;
no-Q/random-Q/G1 при частично доступном t. При паритете с сильной таблицей
основные меры — actual до допуска, байты хранения, цена проверок. Порядок
пар/расширений, домены/кодировка, лимиты сравнений/памяти/чтений и численные
acceptance thresholds фиксируются до данных в будущем протоколе.
Остальные основания NOT_READY сохраняются; подтверждающего запуска здесь нет.
