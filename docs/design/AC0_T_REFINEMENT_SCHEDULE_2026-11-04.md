## 1. Данные fixture и счёт

Одна непрозрачная O. Стационарный внешний закон: a/b→G+, c→G−. Он известен
только описанию/evaluator, learner извлекает последствия из actual. Публичные
типы t∈{a,b,c}, n∈{n0,…,n7}, x∈{x1,…,x8} различны: случайное равенство
между x/n/t не создаёт ещё одного разделителя. Все n/x в таблицах различны,
channel/роль/O постоянны. Опора для относительного G заморожена до операции.

o∈{0,1}, pf — positive frozen forecast, nneg — negative frozen forecast,
p=o+pf. Допуск: p≥2 и p/(p+nneg)>1/2, плюс match/A3/availability.
Создание/уточнение не импортирует поддержку. По X1 создающий actual даёт
origin, лишь если соответствует K и G нового C. У C без origin первый
последующий actual с frozen forecast даёт pf=1, **не** отложенный origin.

Все указанные исполнения — общая forced curriculum с одинаковыми actual
для arms. По N5c прогноз недостаточно поддержанного C замораживается только
при K=match; unknown/reject не дают action forecast. Счётчики ниже —
логические обязательства предложенного schedule, не наблюдённые результаты.

## 2. Исходный первый подходящий разделитель: все шесть порядков

Начало общее: a1=(a,n0,x1,G+); a2=(b,n1,x2,G+) создаёт C0 с
K0=(t=?t,n=?n,x=?x), origin=a2; a3=(a,n2,x3,G+) даёт первый
frozen positive. До a4 C0 имеет (o,pf,nneg)=(1,1,0), p=2, допущен.
На a4=(c,n3,x4,G−) C0 получает nneg=1; t=c, n=n3, x=x4 одинаково
отделяют новый исход от трёх старых. Противоположные записи того же
разбиения (f=v / f≠v с обменом ветвей) считаются одним кандидатом.

| Порядок признаков | Первый split на a4 | Что следует на a5=(c,n4,x5,G−) | Исход расчёта для исходной схемы |
|---|---|---|---|
| t,n,x | t=c | Частный Cc match, positive forecast: o=1,pf=1; дополнение reject | Условно обе ветви допускаются за 7 actual/O, как ниже; t-первый — явный prior |
| t,x,n | t=c | То же | То же |
| n,t,x | n=n3 | Частный Cn reject; расширение по §4.4 может снова дать K0→G−, o=1,pf=0. Дополнение n≠n3→G+ получает negative | Нет гарантии нужного split в бюджете; NOT_READY |
| n,x,t | n=n3 | То же | То же |
| x,t,n | x=x4 | Частный Cx reject; расширение может снова дать K0→G−. Дополнение x≠x4→G+ получает negative | Нет гарантии нужного split в бюджете; NOT_READY |
| x,n,t | x=x4 | То же | То же |

Для двух t-первых порядков, **при уже выбранном правильном split**, после
a4 частный Cc имеет (1,0,0), дополнение Cnotc — (0,0,0). На a5 Cc
получает pf=1 и допускается; a6=(a,n5,x6,G+), a7=(b,n6,x7,G+) дают
дополнению pf=1, затем pf=2 и допуск. Это расчёт с данным правильным выбором,
не доказательство нахождения релевантности и не допустимый скрытый prior гейта.

Для n/x-первых порядков после a5 возникают широкая отрицательная гипотеза
и положительное дополнение с изменяющимися исключениями. Возможный путь:
на очередном новом n/x частная ветвь reject → расширение снова снимает
ограничение n/x; противоположная широкая гипотеза получает negative →
следующий split по новому n/x → новое расширение. Локальные редакции теряют
допуск или конкурируют, нужный t=c не обязан быть выбран.

На a6 с c широкая G− может получить первый forecast и p=2; a7 с a даёт ей
negative и новый частный G+ по n/x; a8 с b может снова расширить его до
широкого G+. Это допустимая неудачная ветвь, **не единственная предсказанная
трасса**. Точный набор других носителей и их счётчики не определяется одним
порядком t/n/x: в принятом дизайне не фиксированы очередность обработки
конфликтов расширенной редакции и повторное использование исполнений,
уже участвовавших в уточнении. Если обычное построение пары G− позднее
создаст корректный Kc, это отдельная возможная трасса; она не превращает
первый подходящий split в гарантию сходимости.

Следовательно, для четырёх порядков нельзя честно записать «обе ветви
допущены к a8». Расчёт не подменяется симуляцией с удобной очередью:
исходная fixture/правило NOT_READY по X2.1. Нужен выбор общего правила
до опыта. Произвольно продлевать curriculum до удачного split нельзя.

## 3. Принятое правило X2.2 с Y1

Канонический критерий — §4, п. 5 [дизайна](T3_GENERALIZED_OPERATION_KEYS_v0_2.md).
После оценки замороженного прогноза обычная консолидация строит конкурирующий K
по исполнениям с одинаковым G, несовместимым с G старого C. Кандидаты — только его конкретные
литералы. Принимается единственный литерал, истинный на всех наблюдённых
противоречащих исполнениях и ложный на всех positive старого C. Unknown
не подтверждает условие. При отсутствии K, отсутствии подходящего литерала
или ничьей уточнение откладывается. Неполная проверка по лимиту или
исчерпанная глубина отложения дают INCOMPLETE.

На a4 конкурирующий K ещё не построен. Три геометрических разделителя,
перечисленные в §2, описывают исходное правило, а не набор кандидатов X2.2.
На a5 пара G− строит Kc с t=c и переменными n/x. Общие channel/роль/O
не исключают старые positive. Остаётся t=c. По X1 у Cc origin=5.
Если Kc/Cc уже задают частную ветвь, используются те же объекты.
Консолидация создаёт Cnotc: K0∧t≠c → G+ без origin и выводит C0 из допуска.
Потеря числового допуска C0 на a5 не исключает его из проверки конфликта.

## 4. Schedule при разных n/x: 8 actual/O

| Actual | (t,n,x), исход | Frozen forecast до actual / изменение | C0 (o,pf,nneg) | Cc | Cnotc |

| 1 | a,n0,x1; G+ | Только исходное исполнение | — | — | — |
| 2 | b,n1,x2; G+ | Пара 1/2 создаёт K0/C0; origin=2 | 1,0,0 | — | — |
| 3 | a,n2,x3; G+ | C0:G+ positive, допуск | 1,1,0 | — | — |

| 5 | c,n4,x5; G− | C0:G+ negative; пара 4/5 создаёт Kc/Cc, origin=5; единственный split, Cnotc без origin | 1,1,2; retired | 1,0,0 | 0,0,0 |

После a4 C0 всё ещё проходит 2/3>1/2; после a5 2/4=1/2 и числовой допуск
пропадает. Retirement после split всё равно нужен: поздний pending старой
редакции не должен вернуть её в действие повышением p. a5 одновременно
negative C0 и origin Cc; это один внешний event, не два независимых опыта.

Одинаковый исход ниже для шести прежних порядков. X2.2 применяет
один критерий к литералам K, поэтому прежний порядок не управляет выбором.

| Прежний порядок | a4 | a5 | a6 | a7 | a8 |
|---|---|---|---|---|---|
| t,n,x | defer | единственный t=c | Cc допущен | Cnotc pf=1 | Cnotc pf=2, допущен |
| t,x,n | defer | то же | то же | то же | то же |
| n,t,x | defer | то же | то же | то же | то же |
| n,x,t | defer | то же | то же | то же | то же |
| x,t,n | defer | то же | то же | то же | то же |
| x,n,t | defer | то же | то же | то же | то же |

Сумма: 3 actual для C0 + 2 противоречащих actual + 1 forecast Cc +
2 forecast Cnotc = **8 actual/O**. Это бюджет только этой условной fixture,
выведенный отдельно. Он не является 8/O двухместностного V3, не включает
closed, Q, causal-пробы, полный manifest или бюджеты гейта. Если в будущем
компонентном тесте не выполнены предпосылки консолидации/полноты обхода,
фиксируется неуспех/INCOMPLETE без изменения N3a и без добавления actual.

### R10 и цена отложения (Y2)

Если у a4 и a5 совпало n=n3, а x различны, конкурирующий K сохраняет t=c
и n=n3. При прежних positive с другими n подходят оба литерала.
Ожидаемый исход R10 на a5 — отложение. Следующее c с другим n может снять
лишний литерал при расширении K. Это иной case, к нему не переносится
число 8 actual/O. Протокол до данных фиксирует размеры доменов, максимальную
глубину отложения и исход INCOMPLETE при её исчерпании.

От первого противоречия до применения split считать observed actual,
не совпавшие с замороженным прогнозом старого C0. Отдельно показывать
forced curriculum и native dispatch. Между a4 и a5 C0 ещё проходит
числовой порог 2/3, поэтому такой прогноз может ошибиться в контексте c.
Счётчик отражает цену отложения и не меняет допуск.

## 5. Q0 и границы проверки

После a8 скрываем доступ к t, сохраняя общий публичный домен {a,b,c} и
меню платных Q. Cc и Cnotc получены этим schedule, а не вручную добавлены.
Оба условия unknown; их ожидаемые множества {c} и {a,b} не пересекаются,
поэтому score(Qt)=1/цена. Для n/x нет разделяющей пары. При недостижимости
этих C исход Q0 — «не достигнут», не работа на другой искусственной паре.
Качество действия на solvable curriculum и итоговый causal gate этим не
проверяются. No-Q/random-Q/G1 и стоимость остаются отдельными arms протокола.

Проверка: построчное применение X1/N3a/N5c, все 6 перестановок t/n/x,
непересечение {c}/{a,b}, неизменность origin/forecast при переносе роли Cc.
Ниже историческая проверка конечных множеств разделителей на данных fixture
(Python, стандартная библиотека). Перебор в скрипте проверяет §2 и уникальность
разбиения на a5. Кандидаты для архитектурного X2.2 определяются по §3. Код можно сохранить во временный
файл и выполнить `python -X utf8 <файл>`; ожидаемый вывод указан в print.

```python
from itertools import permutations
from fractions import Fraction
rows = [dict(t=t, n=f'n{i}', x=f'x{i+1}')
        for i, t in enumerate(('a', 'b', 'a', 'c', 'c'))]

def separators(order, negatives):
    positive = rows[:3]
    found = set()
    for f in order:
        for v in {r[f] for r in positive + negatives}:
            for eq in (True, False):
                match = lambda r: (r[f] == v) == eq
                if all(match(r) for r in negatives) and not any(map(match, positive)):
                    found.add((f, '=' if eq else '!=', v))
    return found

for order in permutations(('t', 'n', 'x')):
    assert separators(order, rows[3:4]) == {('t', '=', 'c'), ('n', '=', 'n3'), ('x', '=', 'x4')}
    assert separators(order, rows[3:5]) == {('t', '=', 'c')}
assert Fraction(2, 3) > Fraction(1, 2) == Fraction(2, 4)
assert not ({'c'} & {'a', 'b'})
assert 3 + 2 + 1 + 2 == 8
print('6 orders: 3 tied splits at a4, 1 split at a5; conditional budget=8')
```

Скрипт и расчёт для fixture не менялись в Y1–Y3. Следующее действие —
ревью диффа Y1–Y3, затем цельный AC0-T с полями Y2. До принятия протокола
код части B и confirming закрыты.
