## 0. Что решает итерация

Требование HANDOFF §2 — «условие → носитель → операция → изменение состояния →
продолжение → свидетельство → эффект снятия и восстановления» — до сих пор не
имело ни носителя для самого процесса, ни прогноза снятия. Итерация даёт:

1. аудит такта по действующему коду (§1);
2. определение зависимого процесса как **производного вида над существующим
   журналом**, без нового хранилища на первом шаге (§2–§3);
3. одно новое правило выбора: заявка на разрешение в точке бифуркации (§4);
4. три статуса завершения с поведенческими признаками (§5);
5. первую причинную пробу на генераторе K1 с прогнозами по построению (§6).

Ответы на вопросы самопроверки HANDOFF §9:

1. *Функция цепи и прекращение.* Обнаружение неразличённости → заявка →
   выделение ресурса → действующий контур → новое устойчивое. Прекращение
   проверяется тремя способами завершения и пробами снятия по классам связи.
2. *Гейт и опровержение.* Причинная часть AC0-L; готовит AC1 (вытеснение и
   возврат). Опровергает §7.
3. *Простой контроль.* Таблица с памятью отказов и бюджетом попыток даст ту
   же цену и то же качество. **Паритет ожидается.** Проба проверяет не
   преимущество, а функциональную связь и её снятие.
4. *Одно действие.* Ревью PR47 ревьюером; пакеты этого дизайна — после Z4.
5. *Запрещено без владельца.* Слияния; протокол AC0-T, часть B, confirming.

## 2. Зависимый процесс

**Точка бифуркации** — тройка (канал, ключ k, команда c), для которой в
журнале есть наблюдённые исполнения с разными целями.

**Зависимый процесс** — всё, что ядро делает из-за одной точки бифуркации: от
первого расхождения до завершения. Он один на точку.

На первом шаге процесс — **чистая функция** от уже хранимого: квитанций и
записей операций, поддержки Gen, состояния applicability guard, квитанций
программы периферии (`executed` / `no_slot` / `stale` / `refused`). Нового
хранилища нет. Хранимое состояние появляется только во втором пакете и только
одно: отметка подавления с моментом возврата (§5).

| Поле вида | Откуда берётся |
|---|---|
| Точка бифуркации | Группа Gen с одним `key_id`, `oper_id` и разными `goal_id`, у каждого есть actual evidence |
| Скрытая фаза | Исполнения в этой точке до первого расхождения: прогноз был, конкурента не было |
| Момент обнаружения | Первая квитанция с целью, отличной от прогноза допущенного Gen |
| Заявки | Предложения команды разрешения в этом ключе (§4) |
| Попытки разрешения | Квитанции программы для запроса вложенной области из k |
| Рост определённости | Доля сбывшихся замороженных прогнозов команды c по ключам, достигнутым из k, за последние попытки |
| Статус | §5 |

Мера скрытой фазы — то, что решение А2 называет авидьей: число исполнений,
где допущенный прогноз был и не сбылся, при отсутствии конкурента. Это число
уже есть в журнале как отрицательные evidence первого Gen точки.

## 3. Условия процесса и их классы

Каждое условие процесса имеет класс связи; класс задаёт прогноз снятия
(ретро §3).

| № | Условие | Носитель | Класс | Прогноз снятия |
|---|---|---|---|---|
| У1 | Ключ k предъявлен | Наблюдение канала | Объект | Ключ не предъявлен — заявок нет; знание не меняется |
| У2 | Расходящиеся прогнозы в точке | Допущенные Gen с разными целями | След | Блок применения одного из них guard — заявки прекращаются на время блока; evidence не меняются; снятие блока — заявки возвращаются |
| У3 | Есть место для команды | Окно драйвера; предел операций | Присутствие | `no_slot` — заявка остаётся, исполнения нет, p и n не меняются; место появилось — исполняется |
| У4 | Приоритет среди заявок | Порядок предложений | Перевес | Появилась заявка выше — эта исполняется позже; доступность не меняется |
| У5 | Точка не подавлена | Отметка подавления | Следование | Пока отметка действует — заявок нет; истекла — заявка возникает без нового расхождения |

Фиктивное вмешательство для каждой пробы: тот же блок, применённый к Gen
другой точки. Прогноз — изменений нет.

## 4. Правило заявки

Сейчас команда с несовместимыми допущенными прогнозами не допускается к
конкуренции по цели (ONTOLOGY, «Ambiguous command»). Ядро воздерживается.

**Дельта.** Если команда исполняется из точки бифуркации (§2), в меню канала
есть запрос вложенной области и точка не подавлена — ядро предлагает запрос
разрешения. Его исход:

- `executed` — получен вложенный ключ k′. Команда c затем исполняется из k′
  обычным путём части A: порождающее исполнение, затем замороженные прогнозы;
- `refused` — вложенной области нет. Это наблюдённый исход запроса, а не
  unknown и не отрицание для Gen точки;
- `no_slot`, `stale` — исполнения не было; попытка не засчитывается.

Уточнение по П1-а (З-0139). Условие — точка бифуркации вида процесса, а не
предикат «неоднозначная команда». При равновероятных ветвях первый Gen точки
теряет допуск (p/(p+n) = 0,5), второй сохраняет; допущенных несовместимых
прогнозов тогда нет, и ядро уверенно выбирало бы по второму Gen. Разные
наблюдённые цели в журнале — признак, который от этого не зависит.

Это общий случай различающей проверки G1: платное действие, исход которого
разделяет конкурирующие прогнозы. Отличие от G1 дизайна T3 одно — возможен
отказ. Выбор по-прежнему делает ядро; драйвер исполняет и отвечает.

Правило не вводит обобщённого K. Уточнённым ключом служит вложенный ключ,
который выдаёт драйвер: топология принадлежит периферии (положение 6). Поэтому
дельта не зависит от закрытой части B.

## 5. Завершение

| Статус | Условие | Что остаётся | Признак при повторном предъявлении |
|---|---|---|---|
| `resolved` | Для каждого вложенного ключа, достигнутого из k, прогноз команды c допущен по N3a и не конфликтует | Цепочка «k, запрос, k′, c, цель»; evidence | Новых расхождений нет; процесс не возникает заново |
| `suppressed` | M попыток подряд без роста определённости либо с отказом | Отметка с моментом возврата; все Gen и evidence | До возврата заявок нет; после — одна заявка без нового расхождения |
| `displaced` | Заявка проиграла по приоритету или не получила места | Сама заявка | Исполняется, когда место освободилось |

Отсутствие исхода (`unknown`, `interrupted`, `cancelled`) — не завершение:
процесс остаётся активным.

Baseline подавления: M = 2, возврат через фиксированное число посещений точки.
Альтернатива для сравнения: возврат по росту определённости в соседних точках
того же канала. Числа фиксирует исполнитель до данных. Владелец разрешил
проектировать этот механизм свободно (З-0118), поэтому baseline обязан иметь
способ провалиться (§7).

`resolved` не означает, что запрос больше не исполняется. Из грубого ключа
запрос нужен при каждом посещении — но уже как шаг освоенной цепочки, а не как
заявка процесса.

## 6. Первая причинная проба

**Стенд.** Генератор K1 без изменений (`PERIPHERY_CONTRACT_v0_1.md`): три места
по два скрытых источника — однозначное, различимое вложением, с недоступным
вложением.

**Плечи.**

| Плечо | Что это |
|---|---|
| Я0 | Действующий путь: при неоднозначности воздержание |
| Я1 | Правило заявки §4 без подавления |
| Я2 | Правило заявки и завершение §5 |
| Т1 | Грубая таблица |
| Т2 | Таблица максимального разрешения: запрос всегда |
| Т3 | Таблица с памятью отказов и тем же бюджетом M |

Все плечи получают одни и те же публичные ключи и исходы. V — число посещений
места после одинакового покрытия; V > M.

**Поправка (З-0140).** Таблица ниже неверна в одной посылке: после
исполненного запроса ветвь драйвера остаётся в разрешённом состоянии, поэтому
во втором месте запрос нужен один раз на ветвь, а не при каждом посещении. Для
плеч Я0, Я1, Т1, Т2 действует прогноз
[P1B_PREDICTION](../../experiments/reports/P1B_PREDICTION_2026-11-12.md), он
подтверждён измерением. Для Я2 и Т3 прогноз будет записан в П1-в. Исходная
таблица оставлена как история.

**R1 по построению: качество / число запросов за V посещений.**

| Место | Я0 | Я1 | Я2 | Т1 | Т2 | Т3 |
|---|---|---|---|---|---|---|
| Однозначное | до 1 / 0 | до 1 / 0 | до 1 / 0; процесс не возникает | 1 / 0 | 1 / V | 1 / до V |
| Различимое вложением | ≤ ½ либо воздержание / 0 | до 1 / V | до 1 / V; статус `resolved` не раньше четырёх посещений | ≤ ½ / 0 | 1 / V | 1 / V |
| Вложение недоступно | ≤ ½ / 0 | ≤ ½ / V | ≤ ½ / M + возвраты; статус `suppressed` | ≤ ½ / 0 | ≤ ½ / V | ≤ ½ / M + возвраты |

«Не раньше четырёх посещений»: два вложенных ключа, каждому по N3a нужны
порождающее исполнение и один сбывшийся прогноз.

Что из таблицы следует до запуска:

- Я2 и Т3 совпадают по цене и качеству во всех трёх местах. Преимущества перед
  таблицей проба не покажет и не должна.
- Я2 отличается от Я1 только в третьем месте — ценой.
- Я2 отличается от Т2 в первом месте: ядро не платит там, где бифуркации нет.
  Это единственное отличие от табличного контроля, и оно уже записано в R1
  контракта периферии.

**Пробы снятия на плече Я2** — собственно предмет пробы.

| Проба | Вмешательство | Прогноз |
|---|---|---|
| С-У1 | Место не предъявляется N тактов, затем предъявляется | Заявок нет; затем поведение как до паузы; evidence не изменились |
| С-У2 | Guard блокирует один из двух Gen точки во втором месте до `resolved` | Заявки прекращаются, ядро действует по оставшемуся прогнозу; после снятия блока заявки возвращаются; evidence заблокированного Gen не изменились |
| С-У2ф | Тот же блок на Gen первого места | Изменений во втором месте нет |
| С-У3 | Драйвер не даёт окна K тактов | Квитанции `no_slot`; статус активен; p и n не меняются; затем исполнение |
| С-У4 | Одновременно активны процессы второго и третьего мест | Порядок исполнения соответствует приоритету; обе заявки исполнены |
| С-У5 | После `suppressed` третье место предъявляется до и после момента возврата | До — ноль заявок; после — ровно одна, без нового расхождения |
| С-З | После `resolved` второе место предъявляется повторно | Новых процессов ноль; отрицательных evidence ноль |

С-У5 против С-З — проверяемое различие подавления и отсечения.

## 7. Что опровергает дизайн

- Любая проба §6 даёт исход, отличный от прогноза своего класса, — класс связи
  условия определён неверно либо пять классов недостаточны.
- Две пробы разных классов неразличимы по исходу — классы избыточны.
- Вид процесса §2 не удаётся вычислить из существующего журнала — нужен
  носитель; тогда стоп и запись, чего именно не хватает.
- Я2 теряет качество во втором месте относительно Я1 — подавление срабатывает
  там, где определённость росла; мера роста негодна.
- Я2 не дешевле Я1 в третьем месте — правило подавления не действует.

Проба не может показать: перенос, преимущество перед таблицей, освоение
замыкания, пригодность правила при большом числе точек. Успех пробы — один
причинно воспроизводимый фрагмент, а не гейт.

## 8. Вне этой итерации

- **Пустое течение** (§1): фильтр, при котором рефлекторный переход,
  совпавший с ожиданием освоенного контура, не вызывает полного такта. Связан
  с результатом PR47 и решается в его ревью, не здесь.
- **Дверь ума.** Одно ограничение уже сейчас: события процесса (обнаружение,
  заявка, статус) испускаются в трассу в форме, которую позже можно выдать как
  тройки. Формат — существующий `AttentionTracer`.
- **Регулятор режимов** по признакам траектории (ретро §9).
- **Обобщённый ключ K** и часть B.
