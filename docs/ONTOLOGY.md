# БАЗОВАЯ ОНТОЛОГИЯ ТЕРМИНОВ FirstAGI

### Статус: действующий словарь (З-0029). Правило: термин без определения здесь
### не используется в коде, телеметрии и документах. Термины теории дхарм —
### только в «Контрольном слое» (§4), никогда как имена сущностей.

---

## 1. Центральное определение

**Элементарный цикл движения внимания** — связка:
неопределённость, привязанная к опоре → побуждение к определённости →
возникновение внимания в виде команд периферии → модель снова и снова
попадает в интересующие её состояния → исследует их устойчивость и
вариативность → обновляет статистику различений.
Всё остальное в системе — обвязка этого цикла. Инженерно: 12 стадий
`AttentionStage` (core/core_types.py), трасса `AttentionTracer`
(core/attention_trace.py), пайплайн `LearningSystem.process_token()`.

## 2. Базовая онтология (первичные термины)

Каждый термин: определение → инженерный референт в каноне.

| Термин | Определение | Референт в коде |
|---|---|---|
| **Признак** | Направленный переход между характеристиками областей восприятия (Δ-вектор); инвариантен к аффинным преобразованиям | `core/feature.py` FeatureVector |
| **Обобщение (Gen)** | Цепочка признаков со статистикой значимости = success/(success+stop); единица знания | `core/generalization.py` Generalization |
| **Суперобобщение** | Обобщение над цепочками обобщений (мета-Gen); композиция, не владение | meta-Gen в `core/dream.py`, консолидация |
| **Субобобщение** | Обобщение, входящее в состав цепочки другого; связь в гетерархии | `GeneralizationBase.link()` |
| **Цепочка обобщений** | Упорядоченная последовательность признаков внутри Gen; длина = chain | `Generalization.feature_chain` |
| **Гетерархия** | Плоская сеть обобщений разных уровней без единого корня: взаимные ссылки, конкуренция и влияние вместо владения; обобщение обобщения — то же обобщение | `GeneralizationBase` |
| **Траектория цепочек** | Путь актуального контекста по гетерархии во времени | `core/attractor.py` TrajectoryRecorder |
| **Перемежающиеся цепочки** | Конкурирующие цепочки, попеременно подтверждающиеся на одном потоке; сырьё арбитража | конкуренты в ContextBuffer |
| **Аттрактор** | Устойчивый паттерн, к которому сходятся траектории внимания в фазовом пространстве признаков | `core/attractor.py` AttractorEncoder |
| **Бассейн устойчивых траекторий** | Множество вариаций, сводимых к одному обобщённому ключу A→B без потери различающей способности | coarsening в AttractorEncoder |
| **Окрестность бифуркации** | Состояние контекста, где ≥2 конкурента предсказывают разные продолжения | `LazyDisambiguator.detect_bifurcation()` |
| **Разрешение в окрестности** | Точность сопоставления при исследовании окрестности: COARSE/MEDIUM/FINE/EXACT; модулируется энергией | `Resolution` (core_types), AttractorEncoder |
| **Ядро** | Токен-агностичный цикл сопоставления и обобщения; один бинарник, никаких ветвлений по типу экземпляра (A-01) | `LearningSystem` + AttractorEngine |
| **Периферийный драйвер** | Преобразователь среда↔токены + исполнитель команд перехода внимания | `drivers/base.py` PeripheralDriver |
| **Системный драйвер** | Драйвер внутренней среды (сон, «материальная награда» по З-0025); эволюционный хак, сменяемый и конкурирующий между поколениями | SleepDriver; TeacherDriver (рефактор S2-2) |
| **Сенсорно-эффекторное пространство** | Множество состояний, достижимых через драйверы: что можно различить и куда можно направить внимание | совокупность драйверов экземпляра |
| **Команда перехода внимания** | Сообщение ядра драйверу «переведи восприятие в состояние X» | `PeripheralDriver.query(feature)`; PROBE/FEED/SEED/RETIRE (контракт v4 §2.2) |
| **Программа команд (в гетерархии)** | Последовательность команд перехода, приводящая из опоры к различению; переносимая единица обучения роя | зона `cmd` токена — задача S2-3 |
| **Опора** | Узел гетерархии с высокой значимостью, якорь для прикрепления новых различений | anchors в `core/curiosity.py`; `f_cur` токена |
| **Брокер внимания** | Выбор следующего зонда/вопроса, максимально снижающего ожидаемую неопределённость | ExplorationPolicy + InitiativeEngine (частично, аудит §2.2) |
| **Менеджер очереди команд** | Упорядочение и доставка команд драйверам: FIFO внутри драйвера, идемпотентность, коммутативность между драйверами | Тело + контракт v4 §2.2 — задача S2-4 |
| **Актуальный контекст** | Множество активных обобщений + история сопоставлений текущего эпизода | `core/context.py` ContextBuffer |
| **Стадии цикла внимания** | 12 упорядоченных событий одного такта: UNCERTAINTY → … → CONTEXT_DECAY | `AttentionStage`, `AttentionTracer` |

## 4. КОНТРОЛЬНЫЙ СЛОЙ: соответствие теории дхарм (правило З-0029)

Назначение слоя — **испытание архитектуры философией**, а не источник имён.
Термины Учения многозначны и интерпретируются каждым существом по-своему;
использовать их как ярлыки кода — значит впрыскивать неопределённость и
давать ложные намёки. Поэтому: (а) в коде и телеметрии — только инженерные
имена; (б) соответствие — явная таблица с обоснованием; (в) расхождение
слоя с инженерией = сигнал пересмотра или честная запись в журнал, а не
переименование.

| Термин Учения | Инженерная сущность | Обоснование соответствия | Статус |
|---|---|---|---|
| 12 нидан пратитья-самутпады | 12 стадий `AttentionStage`; порядок = ассерты CI | цикл возникновения опыта из неведения через контакт, оценку, цепляние к рождению и распаду | ПРОВЕРЯЕТСЯ (тест 12↔12 + ассерты порядка) |
| Авидья | UNCERTAINTY | неведение = зарегистрированная неопределённость | принято |
| Ведана | EVALUATION | тон-оценка исхода контакта | принято |
| Танха / Упадана | DRIVE / RETENTION | жажда-реакция / удержание позиции | принято |
| Джати / Джара-марана | CONTEXT_FIXATION / CONTEXT_DECAY | рождение/распад актуального контекста, не «жизни Gen в базе» | принято (уточнение З-0028) |
| Сантана | Экземпляр ядра с потоковой периферией (один поток опыта) | смертный индивидуальный поток | принято |
| Алая-виджняна | Экземпляр того же ядра, чья периферия — потоки других агентов; хранилище закоммиченных обобщений роя | хранилище семян, осаждение/прорастание = uplink/downlink | принято (гейт E2 — испытание) |
| Биджа (семя) | Закоммиченное обобщение в базе Алаи, ждущее подтверждения разнообразием источников | семя прорастает при условиях | принято |
| Карма | Осаждённая статистика подтверждений, переживающая распад контекста; confirmation_density | действие оставляет след в диспозициях | принято |
| Пунарбхава | Новый экземпляр на опубликованной редакции; отдельно own-resume | метафора наследования, не отдельный дистиллятор и не требование смерти перед публикацией | AC2, З-0047 |
| Анатта | Отсутствие «я»-объекта в системе: нет сущности-носителя, есть поток различений и осаждённая статистика | | принято |
| Ведана-состояния узла | RS6 (шесть состояний достатка/динамики) | | реализация — S2-6 |

## Термины непрерывной платформы (целевой контракт, З-0047)

| Термин | Определение | Реализация сейчас |
|---|---|---|
| Channel | Версионированный интерфейс наблюдений/действий с происхождением событий; не роль/личность | driver_id существует; полный event contract будущий |
| Instance / life | Свой поток внимания, контекст, базовая редакция и локальные кандидаты | LearningSystem существует; полный lifecycle будущий |
| TransitionEvent | Факт выбранной операции и её наблюдённого исхода с seq/provenance/causal parents | будущий adapter; не синоним StepOutcome |
| Support | positive / negative / unknown относительно конкретного Gen | полный трёхзначный протокол ещё нужен |
| Local frontier | Смежные текущим опорам доступные продолжения; малость проверяется | глобальные сканы сейчас встречаются |
| Working delta W | Опыт/кандидаты текущей жизни, не опубликованные автоматически | ProvisionalBase — частичный baseline |
| Revision B | Неизменяемая опубликованная топология с родителями и свидетельствами | отсутствует в целевом смысле |
| Resume checkpoint | Восстановление своей жизни с нужными runtime ссылками/курсорами | pickle LearningSystem частично; не всё приложение |
| Inheritance | Новый экземпляр получает B с пустыми эпизодами; полезность измеряется | не доказано; AC2 |
| Competence | Task success и качество действий на независимых вариантах при явной цене | не число Gen / lexical candidates / текстовый narrative |
| AC0–AC4 | Экспериментальные гейты непрерывного ядра | критерии в FIRSTAGI_OPERATIONAL_PROTOCOL.md |

Один экземпляр может иметь несколько каналов; несколько экземпляров —
отдельные контексты и локальный опыт. Канал не равен экземпляру автоматически.
Названия событий из конституции — целевой словарь; старые enum кода этим
документом не переименованы. Отсутствие пробы — UNKNOWN, а не negative.

## Экспериментальная кодировка операций AC0 (PR22, З-0052)

OperationCodec — stateless кодировка публичного перехода cue→operation:
версия, роль, channel ID, cue ID и operation ID образуют канонический ключ;
SHA-256 даёт ID и шесть числовых координат FeatureVector. Это код различимой
идентичности для debug, не семантическая близость и не новая аксиома ядра.
PredictionFrame — заявленные cue/channel/decision seq/phase/Gen/version
предсказания; проверка совпадения метаданных не доказывает их происхождение.
Abstention — возврат без операции при несовпадающем frame, отсутствии
единственного соответствия или пересечении допусков кандидатов. Decoder
не исполняет операцию и не выдаёт разрешение на неё. Классы находятся только
в experiments/diagnostics/ac0_operation_codec.py, baseline ещё на ревью;
код ядра, реальное обучение и подтверждающие критерии этим не меняются.

## 5. Правила словаря

1. Новый термин → сначала определение здесь (через запись З-NNNN), потом код.
2. Имя в коде/телеметрии — инженерное; дхарма-термин допустим только в §4
   и в комментариях вида «(контрольный слой: …)».
3. Многозначное слово общего языка («сон», «внимание») закрепляется за
   одним инженерным смыслом; остальные смыслы — отдельные термины.
4. Кристальное понимание сначала у команды: если определение нельзя
   рассказать в двух предложениях с указанием кода — термин не готов.
