## Обязательно до manifest / development

**C4 · Роли разрешает ядро, а не внешний код.** `OperationView` несёт готовые
ID native-ролей: `goal_gen_id` и меню `(адрес, operation_gen_id)`. Ядро сверяет
с публичными данными только cue. Проверено: если в меню поменять роли
местами, ядро выбирает другой адрес — оно доверяет сопоставлению, которое дал
runner. В компонентных тестах это безвредно, но в стенде runner, знающий
скрытую перестановку, мог бы направлять выбор. Исправление: меню и цель
приходят публичными токенами (как cue), ядро находит роли через
`find_matching_feature`; тест «перестановка ролей в кадре не меняет выбор
для того же публичного содержания».

**C5 · Побочное обучение при предложении.** `propose_operations` обрабатывает
cue через `process_token`, то есть учится. В scored-фазах v2 это допустимо
только потому, что каждый случай идёт из checkpoint; manifest обязан это
закрепить и проверять хэшем состояния до/после случая.

C3 (байты ≤ 16 MiB, checkpoint с ledger) остаётся в силе.
