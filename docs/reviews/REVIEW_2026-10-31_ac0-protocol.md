## Вердикт

**Принять с поправками P1–P4, затем слить PR #25.** Протокол выполняет D5:
закрытые пары, пороги до данных, сильные контроли, один causal knockout,
заранее записанные решения, честный статус NOT_READY. Главный выявленный им
факт важнее самих чисел: native-выбора операции в ядре нет (`select_goal` —
scaffold). Это и есть критический путь, а не ещё один протокол.

## Проверено ревьюером (статически, без генератора)

Правило `(x + 2y + j + c) % 4 < 2` даёт ровно 2 закрытые операции в каждой из
64 точек обоих каналов; каждый слот виден в training в 32 точках. Значит,
ожидаемые результаты контролей на primary closed известны **до данных**:

| Arm | closed | seen |
|---|---|---|
| exact table | 0.50 (выбор из двух ненаблюдённых) | 1.00 |
| displacement table | 1.00 | 1.00 |
| fixed first / random | 0.25 | 0.25 |

## Поправки

**P1 · Записать аналитические ожидания контролей** (таблица выше) в протокол.
Расхождение реального контроля с ними = INVALID (ошибка генератора/evaluator),
а не результат.

**P2 · Закрыть дыру в таблице решений.** Из P1 следует: «лучше exact на 0.10»
поглощается абсолютным порогом 0.80, а veto «ниже displacement > 0.02» требует
native ≥ 0.98. Явно записать строки: (а) native ≥ 0.98 и все абсолютные
условия → AC0 candidate с формулировкой «паритет со структурным контролем,
преимущество архитектуры не показано»; (б) 0.80 ≤ native < 0.98 → не
candidate, механизм уступает простому структурному объяснению; (в) native ≈
0.50 → native работает как буквальная таблица — решение «равно» из D5.

**P3 · Вынести adaptation/post (фазы 3–4) в AC1.** Чувствительность к смене
правил — критерий AC1 по операционному протоколу, не AC0. Это сокращает
реализацию и бюджет (≈ 2336 вместо 4256 действий/seed). Unknown / отрицание /
interruption (§7) остаются: их требует AC0.

**P4 · Предсказание ревьюера, записанное до данных:** при нынешнем
`Feature.matches` (сравнение векторов, без направления/расстояния) native,
вероятнее всего, ≈ 0.50 на closed. Это не повод подгонять encoding под
displacement: кодирование координат фиксируется в manifest до development и
не меняется после просмотра closed-результатов.
