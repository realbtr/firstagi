## Поправки

**X1 · Origin дочерних C при уточнении — общее правило, без хранилища
предложений.** Предложенное в §3 «предложение без C» добавляет новое
состояние. Есть решение проще, внутри действующих правил:

- Origin — actual, вызвавший создание, **если он удовлетворяет K и G
  создаваемого C**; иначе у C нет origin. Это одна формулировка N5d/W2 для
  пары, расширения и уточнения, без ветвления по типу события.
- Частный C (K0 ∧ t=c → G−): actual4 его создал и удовлетворяет ему,
  значит, это его origin. Для допуска нужен один последующий positive frozen
  forecast.
- Дополнение (K0 ∧ t≠c → G+) создаётся сразу, но без origin; p/n C0 не
  наследуются. По N3a ему нужны два positive frozen forecast. Замораживать их
  можно по N5c, потому что K = match.
- Бюджет тот же, что в варианте Codex (два actual с t ∈ {a,b}), но оба —
  настоящие прогнозы, а новой сущности нет.
- В §2/§3 явно записать, какой G получает каждая ветвь. Частная ветвь
  получает G противоречащего actual, дополнение — неизменную редакцию G
  старого C. В R3 это сейчас не сказано.

R8 при этом выполняется: сразу после одного противоречия ни одна ветвь не
допущена.

**X2 · Достижимость: одно противоречие не определяет разделитель.**
В fixture x и n различны у каждого actual. Против positive a1–a3 actual4
отделяют три литерала: t=c, n=n3 и x=x4. По одному примеру они неразличимы,
и это следует из построения, а не из упущения. Итог тогда задаёт заранее
объявленный порядок перебора, то есть скрытый prior. Если первым выбран t,
это равносильно маске релевантности, которую запрещает §4.5.

Если выбран n, принятые шаги не восстанавливаются. K0 = (t=?t, n=?n, x=?x),
частная ветвь — K0 ∧ n=n3 с t по-прежнему переменной. Следующий actual
(c, n4, x5) ей не распознаётся. Расширение по §4.4 (anti-unification с новым
cue) снова даёт K0, теперь с G−, то есть конфликт с исходным K0 → G+.
Дополнение K0 ∧ n≠n3 → G+ получает новый negative. Возможен цикл без
сходимости к t=c.

До протокола нужно:
1. Рассчитать schedule, как в V3, по шагам для каждого допустимого порядка
   перебора. Если хотя бы для одного допустимого порядка уточнение не
   сходится в бюджете, это исход R1 для fixture и NOT_READY.
2. Рассмотреть правило без скрытого prior, которое выводится из H-T
   («уточнять, когда последствия расходятся»). При ничьей разделителей
   уточнение откладывается. C0 продолжает получать negative: после второго c
   он выходит из допуска уже по N3a (2/4 не больше 1/2). Два противоречащих
   actual (c, G−) образуют обычную пару §4.2, и anti-unification даёт
   K = (t=c, n=?n, x=?x) → G− с origin. Разделитель t=c для уточнения
   K0 → G+ тогда берётся из литералов конкурирующего K, а не из порядка
   перебора. Это вариант для расчёта, а не принятое правило. Выбрать до
   данных и указать бюджет actual.
3. Добавить в таблицу R случай R9: ничья разделителей при одном противоречии
   и наблюдаемый результат выбранного правила.

**X3 · G1 должен работать на продуктах T3, а не на вручную поставленной паре.**
Ka: t=a и Kb: t=b с разными G в fixture §2 не возникают: там a и b дают G+.
Тогда G1 проверяется на паре, которую T3 никогда не построит. Нужно добавить
Q0 на дочерних C из §2: частная ветвь t=c → G− против дополнения t≠c → G+.
Множества ответов {c} и {a,b} не пересекаются при объявленном D(t), и
score(Q_t) = 1/цена. Именно здесь T3 и G1 соединяются (V7). Q1–Q10 оставить
как компонентные случаи.
