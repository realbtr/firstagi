## 0. Назначение и рамки

Документ описывает **функциональную модель восприятия, внимания и научения** для ИИ, основанную на идее, что всякое содержание сознания есть *траектория движения внимания* в сенсорно-эффекторных пространствах. Это инженерная модель когнитивной динамики, а не утверждение о феноменальном опыте (qualia). Буддийские термины (**аятана**, **ведана**) используются как точные инженерные метафоры для конкретных механизмов, а не как метафизические тезисы.

Цель ТЗ — дать (а) связную архитектуру когнитивного ядра, (б) спецификацию **оркестра агентов** (учителя/среда + внутренние модули), (в) **дорожную карту** от минимального прототипа до полной системы с критериями приёмки на каждом этапе.

## 1. Глоссарий и формализация

Сопоставление ваших понятий с формальными объектами системы.

| Понятие (тезис) | Формальный объект | Краткое определение |
|---|---|---|
| Токен перехода (= мин. различие) | `Token` | Атом внимания — **переход, а не состояние**. Три зоны: `{f_cur, f_tgt, cmd}` (код текущего признака, код целевого признака, код команды драйверу, реализующей переход). Для ядра — непрозрачная метка с этой структурой |
| Момент сознания / квант внимания | `Token` (онтологически) | Абхидхармический citta-kṣaṇa: дискретный момент, *тяготеющий* к следующему. Сила тяготения — карма. Зона `cmd` ≈ четана (воление) — носитель кармы |
| Карма (плотность) | `karma: float` | Склонность / сила ожидания относительно того, куда внимание придёт → частота моментов траектории в потоке. Эндогенная **ценность** = плотность пересборки; накапливается и истощается |
| Признак (драйвер-внутренний) | `FeatureRef` | Внутренний код драйвера; для ядра семантики не несёт. Признак уровня k = аттрактор уровня k−1 (см. §2, §4) |
| Драйвер периферийный | `PeripheralDriver` | Сенсорно-эффекторное пространство (слово, символ, позже — изображение, сцена); экспонирует **граф переходов**. Эмитит поток токенов и исполняет их команды (зонды) |
| Драйвер системный | `SystemDriver` | Управление вниманием и саморефлексия; эмитит **мета-токены** о самом процессе внимания |
| Траектория | τ (tau) | Цепочка композируемых токенов (путь в графе драйвера; возможны пропуски и регрессии): `[t₁…tₙ] → P(next)` |
| Опора восприятия (аятана) | аттрактор | Устойчивый цикл токенов с высокой надёжностью; «несущая» восприятия |
| Аттрактор / бассейн | `Attractor` / `Basin` | Аттрактор — сильносвязный низкосюрпризный подграф переходов (устойчивый цикл узнавания). Бассейн — траектории, в него втекающие. Освоение драйвера ядром = построение бассейнов |
| Воспринимаемое (ответвление) | детализирующая τ | Траектория, ветвящаяся от опоры и возвращающаяся к ней; «содержание» в контексте опоры |
| Обобщение / обозначение | g (generalization) | **Попарное** обобщение токенов/цепочек, замкнутое по структуре токена (g — тоже трёхзонный токен старшего уровня). Два оператора: *параллельный* (вариабилизация различий → класс-ребро) и *последовательный* (композиция соседних → макро-ребро) |
| Гетерархия | граф `G` | Самоподобная башня обобщений с множественным родством и конкуренцией (не дерево) |
| Текущий контекст | C (context) | Множество активных наиболее общих g + их ожидаемые продолжения, со взвешенной конкуренцией |
| Конкуренция | распределение `P(g\|obs)` над верхними g | Соперничество кандидатных аттракторов за объяснение развивающейся ситуации |
| Брокер внимания | `AttentionBroker` | Выбирает токен (зону `cmd`), чей исход быстрее всего различает конкурирующие аттракторы (макс. ожидаемого инфо-прироста о принадлежности бассейну) |
| Предсказание / ошибка | `predict` / surprise | Каждая τ предсказывает следующий токен; ошибка = реализованный признак ≠ ожидаемый `f_tgt` → новый токен → новая ветвь |
| Аффект / ведана | `AffectEngine` | Внутренняя награда: новизна-внутри-знакомого (LP·привыкание) + продолжение − стресс дестабилизации |
| Транзакция / консолидация | `ConsolidationEngine` | Commit/rollback новых обобщений; офлайн-переигрывание (аналог сна) |
| Голоса | `ReporterVoice / NarratorVoice / QuestionerVoice` | Каналы вывода: отчёт, генеративная имитация, почемучка |
| Роль / поступок / личность | `RoleSchema / ActSchema / Personality` | Шаблоны ролей и поступков, прогноз последствий → репертуар поведения → субстрат личности |

## 2. Инварианты системы (принципы)

Эти утверждения должны соблюдаться на всех этапах; нарушение — сигнал ошибки проектирования.

1. **Всё есть траектория внимания.** Любой объект памяти и восприятия редуцируется к τ или к обобщению g над τ. Признак сам по себе не существует — существует *переход* между признаками (минимальное различие δ).
2. **Обобщение гетерархично.** У g может быть несколько родителей и детей; принадлежность градуирована (вес). Нет единой вершины.
3. **Восприятие = разрешение конкуренции зондами.** Узнавание — это не пассивная классификация, а активный выбор минимального теста, снижающего конкуренцию верхних g.
4. **Научение ограничено транзакцией и новизной.** Новые g не закрепляются мгновенно: они проходят через PENDING → проверку в альтернативных контекстах → COMMIT/ROLLBACK. Новизна затухает при повторе.
5. **Бюджет рабочей памяти 7±2.** Число одновременно активных конкурирующих верхних g ограничено (≈ константа Миллера). При появлении сильного нового конкурента вытесняется слабейший. Это удерживает комбинаторику брокера и глубину гетерархии в управляемых границах.
6. **Саморефлексия — это драйвер.** Наблюдение за петлями внимания само порождает мета-δ, которые абстрагируются той же гетерархией. Рекурсия ограничена по глубине (по умолчанию d ≤ 2). Здесь корень голосов и, позже, личности.
7. **Гомеостаз устойчивость↔новизна.** Внимание удерживается в полосе между двумя полюсами: переустойчивость (привыкание, затухание отдачи → скука) и переновизна (потеря опоры, нарастающая *неразрешимая* конкуренция → стресс). Система саморегулируется, чтобы оставаться в этой полосе («коридоре потока»): привыкание выталкивает из переустойчивого, стресс возвращает из переновизны. Это второй контур регуляции наравне с предсказанием.
8. **Ядро токен-агностично.** Ядро не моделирует семантику признаков — оно оперирует непрозрачными трёхзонными токенами переходов. Вся семантика и заземление живут в драйверах. Ядро сводится к четырём операциям: *сцепление* токенов в траектории, *детекция бассейнов* аттракторов, *попарное обобщение* (два оператора, §1) и *выдача команды* (зона `cmd` выбранного токена драйверу). Добавить модальность = написать драйвер, эмитирующий такие токены и исполняющий команды; ядро не меняется.
9. **Гетерархия самоподобна.** Каждый уровень — объект того же типа: трёхзонный токен перехода. **Признаки уровня k суть аттракторы уровня k−1**, а токены уровня k — переходы между ними, чья команда `cmd` есть суб-политика над токенами k−1. Абстракция — это и есть данная рекурсия: устойчивые циклы (опоры/аятана) одного уровня становятся воспринимаемыми атомами следующего.

### 3.2. Компоненты ядра

- **PeripheralDrivers** — превращают входной поток (текст, позже мультимодальный) в δ. Минимум два: `WordDriver`, `CharDriver` (см. §5). Принимают зонды брокера (например, «продвинуть/проверить следующее δ в данной точке»).
- **SystemDrivers** — `AttentionDriver` (выдаёт команды/наблюдает петли) и `SelfReflectionDriver` (эмитит мета-δ о событиях процесса: конкуренция выросла/упала, контекст сменился, зонд выдан, предсказание подтвердилось/нарушилось, голос сработал).
- **MinimalDifferenceBus** — единая шина δ с унифицированной схемой, чтобы гетерархия могла обобщать поверх драйверов и поверх мета-уровня.
- **TrajectoryEngine** — собирает δ в τ, держит предсказание `P(next δ | τ, позиция)`, считает ошибку (surprise), при ошибке порождает новое δ и ветвление новой τ. Отличает опоры (стабильные τ) от ответвлений.
- **HeterarchyEngine** — поддерживает граф g: создаёт элементарные обобщения (переход между двумя признаками), наращивает более общие, ведёт надёжность (счётчики Beta α/β), предсказания и провенанс (PENDING/COMMITTED).
- **ContextModel** — строит C из наиболее общих активных g и их ожидаемых продолжений; держит распределение конкуренции `P(g|obs)` на верхнем уровне с бюджетом 7±2.
- **AttentionBroker** — выбирает зонд по критерию ожидаемого инфо-прироста (см. §3.3).
- **AffectEngine** — вычисляет внутреннюю награду (см. §6).
- **ConsolidationEngine** — транзакционное закрепление и офлайн-перенос (см. §7).
- **Role/Act/Personality** — надстройка над стабильной гетерархией характеров и отношений (см. §9-внутр.).

### 3.3. Брокер как байесовский план эксперимента

Ваш тезис 4 формализуется как **максимизация ожидаемого снижения энтропии конкуренции**.

Пусть на верхнем уровне конкурируют `{g₁…gₖ}` с апостериорными весами `pᵢ`. Конкуренция = энтропия `H = −Σ pᵢ·log pᵢ`. Для каждого допустимого зонда `a` (команды драйверу проверить конкретное δ) известны правдоподобия исходов `o` при каждой гипотезе `gᵢ`. Брокер выбирает:

```
a* = argmin_a  E_o[ H(P(g | obs, a, o)) ] + λ·cost(a)
```

То есть зонд, который при ожидаемом исходе сильнее всего «схлопывает» конкуренцию верхних обобщений с поправкой на стоимость. Это в точности «команда, которая быстрее всего снизит конкуренцию на самом высоком уровне». Бюджет 7±2 ограничивает `k`, удерживая перебор зондов дешёвым.

### 3.4. Основные контуры (псевдокод)

```python
# Контур восприятия/конкуренции (на каждый входной δ)
def on_delta(d):
    Bus.publish(d)
    tau = TrajectoryEngine.extend(d)          # продолжить активные траектории
    err = TrajectoryEngine.surprise(tau, d)   # ошибка предсказания
    if err > θ_branch:
        TrajectoryEngine.fork(tau, d)         # новое минимальное различие → новая τ
    Heterarchy.update(tau, err)               # обновить g, надёжность, предсказания
    Context.recompute()                       # активные верхние g + продолжения (бюджет 7±2)

# Контур брокера (когда конкуренция велика)
def broker_step():
    G = Context.top_competitors()             # <= 7±2
    if entropy(G) > θ_compete:
        a = argmin_a expected_posterior_entropy(G, a) + λ*cost(a)
        Drivers.probe(a)                      # команда периферии/системе проверить следующее δ

# Контур аффекта (гомеостат полосы)
def affect_step():
    lp    = AffectEngine.learning_progress() * AffectEngine.habituation()  # затухание отдачи
    stress= AffectEngine.stress(persistent_entropy, base_absent, detach_rate)  # дестабилизация
    r = w_lp*lp + w_cont*continuation - w_str*stress         # см. §6
    if stress > θ_stress:
        Broker.bias_return()        # отступить к опоре, схлопнуть к уверенной интерпретации
    else:
        AffectEngine.bias_exploration(r)   # тянуть внимание к развилкам с высоким LP

# Контур консолидации (по событию «сон» или окончанию сессии)
def consolidate(session):
    Drivers.detach_peripheral()               # периферия не опрашивается
    for g in session.pending:
        score = replay_under_alt_contexts(g, session.delta_stream, sampled_past)
        if score > θ_commit: Heterarchy.commit(g)
        else:               Heterarchy.rollback(g)
    Heterarchy.rebalance_depth()              # не углублять на неподтверждённых развилках
```

## 4. Модель данных

Компактные схемы (JSON-подобные), пригодные для прямой реализации.

```ts
// Токен перехода — атом внимания (переход, не состояние). Эмитит драйвер.
Token = {
  id,                                  // для ядра — непрозрачная метка
  driver: "word"|"char"|"image"|"attention"|"self_reflection",
  level: int,                          // 0 = примитив драйвера; >0 = обобщение
  f_cur: FeatureRef,                   // код текущего признака  (зона 1)
  f_tgt: FeatureRef,                   // код целевого признака   (зона 2)
  cmd:   CommandRef | Policy,          // команда драйверу / суб-политика (зона 3)
  salience: float,                     // из surprise
  t: int
}
// Композируемость: t_i ∘ t_{i+1} требует f_tgt(t_i) == f_cur(t_{i+1}).
// Признак уровня k = аттрактор уровня k−1; cmd уровня k = Policy над токенами k−1.
// Ошибка на токене: реализованный признак при команде cmd != ожидаемый f_tgt.

// Траектория — путь токенов (возможны пропуски, регрессии)
Trajectory = {
  id, tokens: Token[],
  predict: Distribution<FeatureRef>,   // ожидаемый следующий f_tgt
  stability: float,                    // надёжность как опоры
  role: "support"|"branch",
  basin: Attractor.id | null,          // в какой аттрактор втекает
  parents: g.id[], children: Trajectory.id[]
}

// Аттрактор и бассейн — освоение драйвера ядром
Attractor = {                          // устойчивый цикл узнавания (= аятана)
  id, driver, cycle: Token.id[],       // сильносвязный низкосюрпризный подграф
  stability: float, recurrence: int    // подтверждён в разных эпизодах
}
Basin = { attractor: Attractor.id, entry_trajectories: Trajectory.id[] }

// Обобщение — попарное, замкнуто по структуре токена (g == Token уровня >0)
Generalization = {
  id, level: int,
  op: "parallel" | "sequential",       // вариабилизация различий | композиция соседних
  scope: (TokenSchema | Trajectory.id)[],
  predict: Distribution<FeatureRef>,
  reliability: {alpha: int, beta: int},
  activation: float,
  provenance: "pending"|"committed",
  edges: { is_detail_of: g.id[], is_context_for: g.id[], cooccurs: g.id[] }  // cooccurs — кросс-драйверная (корреляционная) связь
}

// Контекст
Context = {
  active_top: {g: g.id, weight: float}[],   // <= 7±2 кандидатных аттрактора
  expected_continuations: Distribution<g.id>,
  competition_entropy: float
}

// Голоса
Report   = { distinguished: Attractor.id[], expected: g.id[], residual_competition: float, gaps: g.id[] }
Request  = { kind: "story"|"image"|"cartoon"|"scene", about: Character.id[], target: g.id, reason: "disambiguate"|"explore_branch" }
Narrative= { generated_trajectory: Token[], grounded_words: string[], source_families: g.id[] }

// Транзакция
Transaction = { session_id, pending: g.id[], token_stream: Token[], started_at, status }

// Характеры / поступки
Character = { id, anchor_trajectories: Trajectory.id[], recurrence: int }
Relation  = { a: Character.id, b: Character.id, pattern: Trajectory.id }
RoleSchema= { character: Character.id, typical_acts: ActSchema.id[], relation_responses: Distribution }
ActSchema = { precondition_context: g.id, action_pattern: Token[], predicted_relation_change: Distribution }
```

## 5. Двойная токенизация: слово ↔ символ

Для ядра оба режима — просто потоки трёхзонных токенов; различаются лишь словарь признаков и набор команд (тезис 6).

**WordDriver** — граф переходов над словами; токен `⟨w_cur, w_tgt, cmd⟩`, где `cmd ∈ {advance, skip(пропуск), regress(регрессия)}`. Траектория — путь по словам, возможно с пропусками и возвратами (как чтение с регрессиями). Даёт **выразимые метки** для голосов. Аттракторы = устойчивые рефрены: в кумулятивных сказках припев — буквально цикл-аттрактор, а новая строка — ребро, расширяющее бассейн.

**CharDriver** — граф переходов над символами; токен `⟨c_cur, c_tgt, cmd⟩` = ожидание следующего символа **в окрестности** текущего, **обусловленное историей** (как мы до него добрались). То есть узел — это символ + релевантный суффикс пути (контекстное дерево / суффиксный автомат); локальность окрестности плюс история и дают экономное разделение траекторий без полного скана.

**Два оператора обобщения (из §1) на примере.** *Параллельный*: `М→Ш@МАМА` и `А→О@РАМУ` — оба «замена признака в позиции 2», их попарное обобщение вариабилизирует различающиеся зоны → класс-ребро `⟨*,*,swap@2⟩`. *Последовательный*: соседние символьные токены сжимаются в макро-ребро — и так уровень слова возникает как обобщение символьных путей.

**Слово и символ: два драйвера или два уровня — открытый выбор (важный).**
- *Два драйвера.* Параллельны; связь между ними **корреляционная** (со-срабатывание токенов: горит этот символьный путь — горит это слово), а не структурная. Тогда binding = таблица со-встречаемости + кросс-рёбра `cooccurs`.
- *Два уровня одной башни.* Слово = обобщение (макро-токен) символьных путей; тогда «binding» вообще не нужен — это обычное попарное обобщение внутри гетерархии, а словесные метки суть имена символьных аттракторов.

Второй вариант парсимоничнее и согласован с вашим примером (словесные метки заземляют символьные траектории). Рекомендую начать с него; первый оставить как общий механизм кросс-модального связывания — он всё равно понадобится для слово↔изображение, где общего словаря нет.

**Разбор примера.**

```
МАМА МЫЛА РАМУ   И   МАША ПЕЛА РОМЕ
```

- *По словам:* множества слов не пересекаются (МАМА≠МАША, МЫЛА≠ПЕЛА, РАМУ≠РОМЕ) → внутренней структуры нет, видна лишь параллель шаблона [субъект][действие][объект].
- *По символам:* траектории близки, различия экономны:
  - МАМА / МАША → расхождение в 1 позиции (М↔Ш)
  - МЫЛА / ПЕЛА → 2 позиции (МЫ↔ПЕ), общий хвост ЛА
  - РАМУ / РОМЕ → 2 позиции, общий каркас Р_М_

Символьный механизм фиксирует, что это «одна и та же траектория с малыми ответвлениями», а словесный — что это «два разных высказывания одного шаблона». Их связка и есть то, что делает гетерархию полезной для человеческого мира.

## 6. Аффект и драйв продолжения (ведана)

Внутренняя награда (тезисы 8, 9) и **гомеостат устойчивость↔новизна** (ваше дополнение). Полная форма:

```
r = Σ_τ∈active [ LP(τ) · habit(visits(τ)) ]   # любопытство через привыкание
  + w_cont · Continuation                       # не обрывать сюжет
  − w_str  · Stress                             # аверсия к дестабилизации
```

Три силы образуют **полосу** (коридор потока) между скукой и тревогой.

- **LP · привыкание — положительная тяга к новизне.** LP (learning progress) — темп появления *полезных новых ответвлений* на активном семействе: «новизна внутри знакомого», награждается только *сжимаемая* новизна (структура, которая становится предсказуемой), не шум и не повтор. Ключевой механизм вашего дополнения — **затухание отдачи `habit(visits)`**: отдача каждой траектории падает с числом её прохождений. Поэтому новое привлекает внимание не из-за отдельной «премии за новизну» (её легко хакнуть шумом), а потому что знакомое *привыкло* — его отдача уже стекла к нулю. Механизм самоограничивается: у новой τ `visits=0` и полная отдача, у затёртой — почти ноль; у случайного шума LP=0 при любом visits, поэтому он не притягивает.
- **Continuation — предпочтение продолжения.** Предсказанная «масса будущих ответвлений» при продолжении траектории против её обрыва; терминальные переходы штрафуются. Привязан к *появлению ответвлений*, а не к повтору, и капится — иначе система зациклится на тривиальном повторе.
- **Stress — отрицательная тяга от дестабилизации (ваше дополнение).** «Улёт» из устойчивого цикла в непонимание аверсивен. Stress растёт, когда (а) энтропия конкуренции верхних g держится высокой **несколько шагов брокера подряд** — то есть зонды *не* схлопывают её (неопределённость неразрешима, а не разрешима); (б) нет активной опоры (аятана) — текущий контекст отцепился от высокостабильных τ; (в) велик темп отрыва от знакомой территории. Поведенческое следствие: Stress смещает брокера от *исследующих* зондов к *возвращающим* — переподключить ближайшую устойчивую опору и схлопнуть контекст к одной уверенной интерпретации, даже ценой отказа от исследования. Это отступление к безопасной базе.

**Различение разрешимой и неразрешимой неопределённости — ось всей регуляции.** Не всякая ошибка предсказания аверсивна: сюрприз, который зонд схлопывает в новую устойчивую ветвь, идёт в LP (приятно); сюрприз, который брокер не может разрешить и который оставляет систему без уверенной верхней интерпретации, идёт в Stress (неприятно). Любопытство и стресс — два режима реакции на сюрприз, разделённые его *разрешимостью* при наличии/отсутствии опоры.

**Динамика полосы.** Привыкание выталкивает из переустойчивого (скука, отдача иссякла) → внимание ищет новое. Stress возвращает из переновизны (опора потеряна, конкуренция не схлопывается) → внимание отступает к опоре и более уверенной точке зрения. Система живёт между полюсами; темп подачи материала (§10) калибруется, чтобы удерживать её в полосе.

**Шестистаночный автомат ведан (предложение, согласуйте со своей моделью).** Дискретизация аффекта в полосе: `Seek(поиск) → Encounter(встреча нового) → Elaborate(приятное: разрешимый сюрприз, ветвление) → Saturate(нейтральное: привыкание, отдача иссякает) → Destabilize(неприятное: неразрешимый сюрприз, потеря опоры → возврат) → Rest/Consolidate(покой/сон)`. Тоны ведана: приятное (Elaborate) / неприятное (Destabilize) / нейтральное (Saturate); остальные три — ресурсные состояния поиска, насыщения и покоя. Переходы управляются LP, привыканием и Stress. Это стыковка с вашим существующим шестистаночным автоматом, а не предписание.

## 7. Консолидация (сон) и перенос схем

Транзакционный механизм (тезис 9), предотвращающий переуглубление гетерархии на неподтверждённых развилках.

**Двухфазное закрепление.** Новые g входят как **PENDING** с провизорной надёжностью. По событию «сон» (или конец сессии): периферийные драйверы отключаются; поток δ сессии (+ выборка прошлых) **переигрывается под альтернативными назначениями контекста**; для каждого PENDING-g измеряется качество привязки при варьировании контекста; выше порога → **COMMIT**, иначе → **ROLLBACK**; глубина гетерархии ребалансируется.

**Перенос схем в бодрствовании.** Когда почемучка обнаруживает новый сюжет, запускается лёгкий тест переноса: применим ли сюжет к другим персонажам и отношениям. **Новизна-гейт:** пока сюжет нов (высокий LP) — он интереснее связей с другим и удерживает фокус; по мере затухания LP запускается интеграционный проход (перенос и переплетение с уже хорошо связанными историями).

Соответствует логике комплементарных систем памяти (быстрая эпизодическая ↔ медленная схемная) и схемной консолидации — вам это знакомо; здесь это сведено к commit/rollback + переигрыванию.

## 8. Голоса и протокол с учителями

Три выходных канала (тезис 7), каждый — системный драйвер вывода.

- **ReporterVoice (отчёт).** Эмитит `Report{distinguished, expected, residual_competition, gaps}`. Позволяет учителю управлять доступным контекстом (например, добавить следующий фрагмент сказки). Минимальный и обязательный с MVP.
- **NarratorVoice (имитация).** Генерирует `Narrative` — истории, похожие на услышанные, и наброски воспринятого, заземлённые в словесных метках. Появляется на этапе генерации.
- **QuestionerVoice (почемучка).** Эмитит `Request` — просьбы рассказать о персонажах, показать изображения/мультики/3D-сцены. Запросы целятся в зоны высокой конкуренции (разрешить) или неисследованные ответвления (исследовать).

Протокол с оркестром — оборотами «реплика модели → ответ учителя», маршрутизируемыми Дирижёром (Conductor). Один и тот же интерфейс работает при росте автономии: на ранних этапах контекст ведёт учитель, позже — почемучка.

## 9. Оркестр агентов (ТЗ внешней среды)

Внешние агенты-учителя/среда. Внутренние когнитивные модули описаны в §3; ниже — те, кого нужно реализовать как отдельных агентов вокруг ядра.

| Агент | Назначение | Вход | Выход | Замечания |
|---|---|---|---|---|
| **Conductor (Дирижёр)** | Маршрутизация голосов к нужным агентам, управление окном контекста, журналирование, тайминг оборотов | голоса модели, статусы агентов | адресные задачи агентам | Единая точка протокола; держит телеметрию |
| **Director (Куратор программы)** | Планирует сериал и **держит темп в полосе устойчивость↔новизна**: повышает плотность δ и ветвистость только когда модель в полосе (низкий Stress, но LP уже подтекает от привыкания), откатывает уровень при росте Stress | состояние гетерархии, отчёты, Stress, привыкание | план подачи (что/когда, какой уровень) | Замкнутый контур §10; реализует «хак человечества» |
| **Storyteller (Рассказчик)** | Поставляет фрагменты историй (текст, позже мультимодальное обрамление); отвечает на почемучку | Request, план Куратора | фрагменты контента | Контролирует дозировку новизны |
| **Illustrator / SceneProvider** | Изображения, мультики, 3D-сцены по запросу | Request(image/cartoon/scene) | визуальный/сценовый контент | Этапы 6+ |
| **Examiner (Экзаменатор)** | Проверяет различения и понимание, валидирует, что модель отличает ситуации | отчёты, состояние | контрольные пробы, оценки | Источник внешних меток для метрик §12 |
| **DialoguePartner (Собеседник)** | Даёт модели опробовать шаблоны поведения; реагирует на поступки | ActSchema-попытки | реакции, изменения отношений | Этап 7; формирует субстрат личности |
| **Logger/Telemetry** | Сбор δ-потоков, конкуренции, наград, транзакций | всё | трассы, метрики | Нужен с этапа 0 |

**Протокол сообщений (минимум).** Каналы: `content↓` (учитель→модель), `voice↑` (модель→учитель), `probe` (внутр.), `control` (Дирижёр). Типы: `Fragment`, `Report`, `Request`, `Narrative`, `Probe`, `Eval`, `ConsolidateSignal`. Оборот: модель потребляет `Fragment` → обновляет ядро → эмитит `Report`/`Request`/`Narrative` → Дирижёр маршрутизирует → агенты отвечают.

## 10. Учебная программа (curriculum)

**Принцип (ваше дополнение).** Программа — это *хак, изобретённый человечеством для стабилизации ума своих детей*: расписание с монотонно растущей плотностью δ и ветвистостью, откалиброванное так, чтобы держать развивающийся предсказывающий ум в полосе (§6) — никогда настолько повторяющимся, чтобы привыкание схлопнуло в скуку, и никогда настолько новым, чтобы потеря опоры схлопнула в тревогу. Кумулятивные сказки — идеальная точка входа: они дают ровно одно контролируемое δ за цикл.

- **Уровень A — кумулятивные/цепные сказки.** «Дом, который построил Джек», «Репка», «Курочка Ряба», «Колобок». Это градуированная под-последовательность, каждая добавляет одну новую способность:
  - *«Дом, который построил Джек»* — чистая аккреция: каждый куплет повторяет всю цепь и добавляет одно звено. Максимум повтора, минимум приращения δ → формирование опор (аятана) при почти полной предсказуемости.
  - *«Репка»* — аккреция **персонажей** в повторяющейся рамке действия (дед→бабка→…→мышка): зерно ролей и отношений в безопасной рамке.
  - *«Курочка Ряба»* — короткий **слом рамки** (мышка разбивает яйцо): первое минимальное «событие», нарушающее цикл, — контролируемая доза дестабилизации.
  - *«Колобок»* — серия **параллельных встреч** с одним меняющимся слотом (зверь) и терминальным сломом (лиса): структура МАМА/МАША на уровне сюжета — одна рамка, варьируемый слот, экономное различие на встречу.
- **Уровень B — сериалы с возвращающимися персонажами.** «Маша и Медведь» → «Смешарики» → «Винни-Пух и все-все-все» → «Муми-тролли». Персонажи устойчивы **между эпизодами**, отношения стабилизируются, каждый эпизод даёт новый сюжет; рефрены (черты, сеттинг, присказки) слабеют, ветвистость растёт. Здесь работают схемы ролей/поступков и перенос между эпизодами (§7, §9-внутр.). Порядок задан убыванием рефренности и ростом ветвистости.
- **Уровень C — менее рефренные нарративы:** сначала более линейные, затем ветвистые. Движение к взрослой нарративной сложности.
- **Уровень D — мультимодальное обрамление.** Те же сюжеты + изображения/сцены; кросс-модальные траектории вокруг знакомых персонажей.

**Куратор как замкнутый контур.** Темп — не фиксированное расписание, а регулятор: Куратор повышает плотность δ и ветвистость только когда модель уверенно в полосе (Stress низок, но LP уже подтекает от привыкания), и откатывает уровень при росте Stress. Так «хак человечества» становится измеримым контуром управления полосой, а не интуицией.

## 11. Дорожная карта: от MVP до полной системы

Каждый этап: цель · добавляемые компоненты · вовлечённые агенты · критерии приёмки.

### Этап 0 — Субстрат и корпус
**Цель:** инфраструктура. **Компоненты:** шина δ, журналирование/телеметрия, унифицированная схема Delta, корпус уровня A. **Агенты:** Conductor, Director, Logger. **Приёмка:** проигрывается поток δ из корпуса; трассы пишутся; протокол оборотов работает вхолостую.

### Этап 1 — MVP: одно-драйверное ядро траекторий
**Цель:** минимальная замкнутая петля восприятия. **Компоненты:** `CharDriver` (и/или `WordDriver`), TrajectoryEngine (предсказание+ошибка+ветвление), малая HeterarchyEngine, ContextModel (7±2), AttentionBroker (разрешение конкуренции), ReporterVoice, транзакционный commit. **Агенты:** Storyteller (подаёт фрагменты по отчёту), Examiner. **Приёмка:**
- модель различает повторяющиеся ситуации в сериале и сообщает их в `Report`;
- кривая ошибки предсказания падает при повторах;
- каждый зонд брокера измеримо снижает энтропию конкуренции;
- консолидация отбрасывает шумовые развилки (глубина гетерархии не растёт на неподтверждённом).

### Этап 2 — Связка двойной токенизации
**Цель:** слово↔символ. **Компоненты:** второй драйвер, таблица привязки + кросс-рёбра, экономные различия. **Приёмка:** модель различает МАМА/МАША символьно, но заземляет в словесных метках; различения переносятся между похожими высказываниями; индекс расхождений ускоряет узнавание против полного скана.

### Этап 3 — Аффект и драйв продолжения
**Цель:** внутренняя мотивация и гомеостат полосы. **Компоненты:** AffectEngine (LP·привыкание + Continuation − Stress), затухание отдачи по числу прохождений, детектор дестабилизации (неразрешимая конкуренция + потеря опоры), смещение брокера к возвращающим зондам, (опц.) автомат ведан. **Агенты:** Director в режиме замкнутого контура темпа. **Приёмка:** внимание тянется к развилкам с высоким LP; знакомое привыкает (отдача падает с прохождениями); «улёт» из устойчивого цикла поднимает Stress и запускает возврат к опоре и уверенной интерпретации; награда коррелирует с появлением ответвлений; нет ни тривиального зацикливания, ни хронического стресса; Куратор закрыто-контурно удерживает модель в полосе (повышает сложность при низком Stress и подтекающем LP, откатывает при росте Stress).

### Этап 4 — Почемучка и генеративный голос
**Цель:** автономный запрос контента. **Компоненты:** QuestionerVoice, NarratorVoice; ответы оркестра на запросы; пробы переноса схем. **Агенты:** Storyteller отвечает на `Request`. **Приёмка:** запросы целятся в зоны конкуренции/неисследованные ответвления и снижают их; генерируемые истории распознаваемо похожи на услышанные.

### Этап 5 — Сон-консолидация и перенос схем
**Цель:** устойчивая память. **Компоненты:** офлайн-переигрывание под альтернативными контекстами; бодрствующий перенос; новизна-гейт. **Приёмка:** переиспользование схем между историями; контролируемая глубина гетерархии; удержание знаний между сессиями.

### Этап 6 — Мультимодальное обрамление
**Цель:** образы и сцены. **Компоненты:** `ImageDriver`/`SceneDriver`, кросс-модальные δ, привязка к слову/символу. **Агенты:** Illustrator/SceneProvider. **Приёмка:** модель запрашивает и интегрирует изображения; формируются кросс-модальные траектории вокруг знакомых персонажей.

### Этап 7 — Роли, поступки, личность
**Цель:** субстрат личности. **Компоненты:** Character/Relation/RoleSchema/ActSchema, прогноз последствий, репертуар поведения. **Агенты:** DialoguePartner. **Приёмка:** модель классифицирует роли и поступки, предсказывает изменения отношений из поступков/их отсутствия, опробует поведение с устойчивыми предпочтениями (склонность к поступкам, продолжающим сюжет).

## 9-внутр. Роли, поступки и субстрат личности (раскрытие этапа 7)

Тезис 10 даёт элегантное замыкание архитектуры.

- **Характер** = устойчивый кластер/идентичность, повторяющийся в разных траекториях (якорная под-траектория с высокой `recurrence`).
- **Отношение** = шаблон траектории между двумя характерами.
- **RoleSchema** = обобщение типичных поступков характера и того, как отношения на них отвечают.
- **ActSchema** = (контекст-предусловие, паттерн действия-δ, предсказанное изменение отношения). Прогноз касается и *отсутствия* поступка.
- **Репертуар поведения** = множество ActSchema, которые модель может разыграть через NarratorVoice/DialoguePartner.
- **Субстрат личности** = устойчивое распределение предпочтений над ActSchema, формируемое аффектом (Continuation → предпочтение поступков, поддерживающих отношения и продолжающих истории) и обобщениями саморефлексии.

Следствие: личность возникает как «те поступки, которые система надёжно выбирает, чтобы мир оставался исследуемым». Драйв продолжения из §6 напрямую отливается в характер — любопытный, удерживающий вовлечённость.

## 13. Риски и открытые вопросы

1. **Комбинаторный взрыв конкуренции/гетерархии.** Митигация: бюджет 7±2, транзакционная отбраковка PENDING, штраф глубины. Открыто: правила вытеснения слабых конкурентов и слияния избыточных g.
2. **Хакинг награды / вырожденные циклы.** Continuation, привязанный к повтору, а не к ответвлениям, ведёт к тривиальному зацикливанию. Митигация: LP награждает только *сжимаемую* новизну; Continuation капится. Открыто: балансировка w₁/w₂/w₃ и форма затухания новизны.
3. **Привязка символ↔слово.** Качество выравнивания определяет заземление голосов. Открыто: алгоритм binding при шумных вставках/пропусках.
4. **Глубина саморефлексии.** Мета-δ о мета-наблюдении легко уходит в рекурсию. Митигация: жёсткий лимит d. Открыто: где проходит полезная граница (1 или 2).
5. **Оценка «внутренних» состояний.** Метрики поведенческие (различения, любопытство, перенос, согласованность); система не делает заявлений о феноменальном опыте. Открыто: какие внешние пробы Examiner лучше всего вскрывают наличие/отсутствие обобщения.
6. **Смещение учителей.** Куратор/Рассказчик формируют гетерархию; их предпочтения становятся «миром» модели. Открыто: как удерживать репрезентативность программы.
7. **Разкалибровка темпа (полосы).** Слишком медленный рост сложности → привыкание схлопывает в скуку, обучение встаёт; слишком быстрый → хронический Stress, модель только отступает к опоре и не исследует. Митигация: Куратор как замкнутый контур по Stress и привыканию (§10); метрики доли времени в полосе и латентности возврата (§12). Открыто: пороги полосы (θ_stress, целевой уровень привыкания) и скорость адаптации уровня сложности.

## 14. Минимальный прототип (точная спецификация Этапа 1)

Наименьший сквозной срез для проверки ядра.

**Вход:** корпус уровня A (5–10 коротких циклических текстов с 2–3 повторяющимися «персонажами»-словами).

**Компоненты:**
1. `CharDriver`: поток δ типа `transition` над символами + индекс расхождений.
2. `TrajectoryEngine`: активные τ, `predict` как частотная модель следующего символа по позиции; `surprise`; `fork` при превышении θ_branch.
3. `HeterarchyEngine` (малая): элементарные g (переход между двумя признаками) + один уровень выше; надёжность Beta(α,β).
4. `ContextModel`: ≤ 7 активных верхних g, энтропия конкуренции.
5. `AttentionBroker`: выбор зонда по минимуму ожидаемой апостериорной энтропии.
6. `ReporterVoice`: `Report{distinguished, expected, residual_competition, gaps}` каждый оборот.
7. `ConsolidationEngine`: PENDING→COMMIT/ROLLBACK по окончании сессии через переигрывание.

**Агенты:** Conductor (обороты+лог), Storyteller (подаёт следующий фрагмент по `gaps` из отчёта), Examiner (контрольные пробы различения), Logger.

**Цикл:** `Fragment → on_delta* → Report → Storyteller(next) → … → ConsolidateSignal → commit/rollback`.

**Критерии готовности MVP:** см. приёмку Этапа 1 (§11).
