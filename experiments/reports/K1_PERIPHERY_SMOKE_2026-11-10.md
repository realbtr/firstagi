# K1 · Smoke потока переходов

10 ноября 2026, шаг 3 по З-0123. Драйвер реализует
[предложенный контракт K1](https://github.com/realbtr/firstagi/blob/0490a6f3984eafbc8bbb85701f723de535867ca6/docs/design/PERIPHERY_CONTRACT_v0_1.md).
Пять тестов на уровне драйвера охватывают воспроизводимый рефлекс, вставку
программы и отсутствие места, возврат для шести исходных ветвей, устаревание
после возвращения к тому же ключу, раскрытие и отказ во вложении.

Запуск из корня репозитория:

```text
python -m pytest -q tests/test_nested_region_driver.py
python experiments/diagnostics/k1_periphery_smoke.py
```

Smoke использует первый случай закрытой перестановки fixture для seed 17,
24 рефлекса подряд и пустую программу. Адаптер передаёт три публичных ID
как признак в существующий `LearningSystem`. У каждой доставки свой token ID.
Политика точного совпадения векторов фиксирует границу проекции.

| Мера | Наблюдение |
|---|---:|
| Доставленные переходы | 24 |
| Пары рефлексов с возвратом к публичному ключу | 12 |
| Gen в базе по завершении | 24 |
| Gen с `success_count > 1` | 0 из 24 (0%) |
| Посещения записей по счётчику GenBase | 5, 9, затем 22 раза по 8 (190, среднее 7,92) |
| Сериализация LearningSystem, pickle protocol 5 | 9 904 байта |
| Записи actual evidence | 0 |

Посещения охватывают операции, обслуженные измерителем GenBase. Размер
относится к ядру в этом прогоне и исключает драйвер и журнал smoke.
12 возвратов произведены рефлексами драйвера. Метрика
повторного подтверждения относится к токенной цепочке, её нельзя переносить
на допуск A1. Опыт ограничен одним потоком. Отдельно остаётся проверить
самостоятельное воспроизведение контура, выбор запроса разрешения и
повторное подтверждение высокоуровневых цепочек.

## Наблюдательная трасса того же потока

`python experiments/diagnostics/k1_periphery_smoke.py --trace` добавляет
ожидания до шага, исход и счётчики совпадающих атомов до и после. Чтения
трассировки вынесены за интервал измерителя. Seed, входы и вызов ядра те же.
Два входных Feature ID обозначены A и B, каждый поступил 12 раз.

| Шаг | Вход | Ожидание до шага | Известные атомы этого входа до → после | Исход |
|---|---|---|---|---|
| 1 | A | пусто | 0 → 1 | COMPLETED, первый атом A с одним подтверждением |
| 2 | B | пусто, прежний A завершён | 0 → 1 | REFUTED, создаётся B |
| 3 | A | B | 1 → 2 | REFUTED, прежний A не получает подтверждения |
| 4 | B | A | 1 → 2 | REFUTED, прежний B не получает подтверждения |
| 24 | B | A | 11 → 12 | REFUTED, ни один прежний B не укрепляется |

Итого один COMPLETED и 23 REFUTED. На всех 22 повторных входах активное
ожидание было противоположным. Каждый такой шаг добавил атом, не увеличив
`success_count` ни у одного уже известного атома этого входа. По коду
[загрузка по входному признаку](../../core/algorithm.py#L170) возможна при
пустом контексте. [Обработчик несовпадения](../../core/algorithm.py#L268)
создаёт и активирует новый атом наблюдённого признака, даже если в базе уже
есть атом с тем же каноническим признаком. Так объясняется накопление дублей
на наблюдённом чередовании. Трасса не оценивает эффект другой политики.

Предложение для ревью. Сначала согласовать парную проверку обновления
контекста из одного снимка на повторном входе. Затем решать, нужен ли
пересмотр повторного распознавания. Самостоятельный запрос разрешения пока
не различит эту проблему доставки к ожидающему Gen.
