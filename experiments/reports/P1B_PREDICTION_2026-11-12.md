# П1-б · Прогноз по построению: заявка на разрешение в точке бифуркации

12 ноября 2026. Записан до кода. Дизайн:
[DEPENDENT_PROCESS_v0_1](../../docs/design/DEPENDENT_PROCESS_v0_1.md), §4, §6, §9 п. 2.
Ветка идёт поверх П1-а (PR48). Статус будущего прогона — smoke; не гейт.

## Поправка к R1 дизайна, сделанная до запуска

Таблица R1 дизайна §6 считала один запрос на каждое посещение второго места.
Для действующего драйвера это неверно: после исполненного запроса ветвь
остаётся в разрешённом состоянии и дальше показывает вложенный ключ. Запрос
во втором месте нужен один раз на ветвь, а не V раз. Таблицы ниже заменяют R1
дизайна для плеч Я0, Я1, Т1, Т2.

## Стенд

- `make_fixture(17)`, один канал, один экземпляр, восемь кругов. В круге одна
  **проба** на ветвь в порядке фикстуры; всего 16 проб на место.
- Проба. Оценщик пустыми тактами приводит ветвь на сторону A в такт, где у
  драйвера есть место для команды. Плечо видит текущий ключ и может сделать
  **не более одной** попытки запроса вложенной области. После попытки оценщик
  снова приводит ветвь на сторону A. Затем плечо даёт прогноз цели команды
  движения из текущего ключа либо воздерживается, и исполняется `MOVE`.
- Программные команды со стороны B не подаются. Рефлекторные переходы во время
  ожидания ядру не передаются.
- Все команды идут через журнал операций части A. Отказ драйвера записывается
  квитанцией `unavailable` и отменой операции: p и n не меняются.
- Прогноз ядра — цель, общая для всех допущенных по N3a Gen среди замороженных
  прогнозов операции; если допущенных нет либо их цели различны —
  воздержание.

## Плечи

| Плечо | Правило |
|---|---|
| Я0 | Ядро без запросов |
| Я1 | Ядро запрашивает вложенную область, когда (текущий ключ, движение) — точка бифуркации вида процесса |
| Т1 | Таблица «ключ → самая частая наблюдённая цель»; при равенстве и без данных воздержание; запросов нет |
| Т2 | Та же таблица, но запрос в каждой пробе |

## Вывод

Обозначения: в каждом месте f — ветвь, идущая в круге первой, s — второй.
В местах 1 и 2 цели ветвей разные, в месте 0 общая.

**Я0, места 1 и 2.** Круг 1: f воздерживается (прогноза нет), s
воздерживается (Gen f не допущен), исход s расходится. Круг 2: f
воздерживается (ни один Gen не допущен); после него Gen f имеет p = 2, n = 1 и
допущен, поэтому s предсказывает цель f и ошибается. Дальше допуск
переходит от одного Gen к другому после каждой пробы, и допущен всегда Gen
*предыдущей* ветви: каждая проба с круга 3 ошибочна.

**Я1, место 1.** Круг 1 как у Я0; точка обнаружена на пробе s. Круг 2: обе
ветви запрашивают вложенную область и получают свой вложенный ключ; прогноза
из него ещё нет — воздержание. Круг 3: Gen вложенного ключа имеет p = 1, не
допущен — воздержание. С круга 4 — верно. Запросов больше нет: ключ уже
вложенный.

**Я1, место 2.** Как Я0, плюс один отказ на пробу начиная с круга 2.

**Место 0, ядро.** Круг 1: обе пробы — воздержание (нет прогноза; Gen не
допущен). Дальше верно. Точка не бифуркация, запросов нет.

**Т1.** Место 0: первая проба — воздержание, остальные верны. Места 1 и 2:
f всегда при равном счёте — воздержание; s всегда предсказывает цель f —
ошибка.

**Т2.** Места 0 и 1: первая проба ветви — исполненный запрос и воздержание
(новый ключ), остальные семь — отказ (ветвь уже разрешена) и верный прогноз.
Место 2: отказ в каждой пробе, прогноз как у Т1.

## Прогноз: 16 проб на место

Формат: верно / неверно / воздержание; попытки запроса (исполнено + отказ).

| Место | Я0 | Я1 | Т1 | Т2 |
|---|---|---|---|---|
| 0, однозначное | 14 / 0 / 2; 0 | 14 / 0 / 2; 0 | 15 / 0 / 1; 0 | 14 / 0 / 2; 16 (2 + 14) |
| 1, различимое вложением | 0 / 13 / 3; 0 | 10 / 0 / 6; 2 (2 + 0) | 0 / 8 / 8; 0 | 14 / 0 / 2; 16 (2 + 14) |
| 2, вложение недоступно | 0 / 13 / 3; 0 | 0 / 13 / 3; 14 (0 + 14) | 0 / 8 / 8; 0 | 0 / 8 / 8; 16 (0 + 16) |
| Всего попыток | 0 | 16 | 0 | 48 |

Вид процесса у Я1 после прогона: точки бифуркации команды движения — грубые
ключи мест 1 и 2; попыток разрешения 2 и 14; статус обоих — активен
(завершения в П1-б нет). Команда запроса из грубого ключа места 1 сама даёт
два разных вложенных ключа и попадёт в вид как отдельная точка с разными
целями; заявок по ней нет.

## Что из этого видно до запуска

- Я1 платит только там, где есть бифуркация: 16 попыток против 48 у Т2.
- Я1 уступает Т2 во втором месте по воздержаниям (6 против 2): ядро ждёт
  допуска по N3a и обнаруживает бифуркацию на круг позже. Это цена правила
  допуска, а не правила заявки.
- В третьем месте Я1 платит 14 отказов без пользы. Это предмет П1-в.
- Я0 в местах с бифуркацией хуже таблицы по числу ошибок: 13 против 8. При
  строгом чередовании ветвей допущенным оказывается Gen предыдущей ветви.

## Что опровергнет

- Любая клетка таблицы расходится с измерением.
- Я1 делает запрос в месте 0 либо из вложенного ключа.
- Отказ драйвера меняет p или n какого-либо Gen.
