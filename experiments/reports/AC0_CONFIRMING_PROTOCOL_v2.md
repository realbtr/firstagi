## 1. Какое решение должен изменить опыт

Проверяется узкая способность: ядро использует обученный переход для выбора
полезной операции в двух каналах, включая невстречавшееся сочетание cue/action,
а отключение его причинного носителя изменяет локальное продолжение.
Сильные альтернативы — точная таблица переходов и таблица выученных смещений.
Объём параметров, match rate, количество Gen и двенадцать названий стадий
не являются критерием. Полный цикл возникновения/прекращения, AC1 и наследник
AC2 этим опытом не доказываются.

Главный риск до запуска: предыдущий `FrozenGoalPredictor`/`select_goal` —
scaffold выбора, а не native policy. Его перенос под новым именем запрещён.
Если существующие компоненты не выбирают исполнимую операцию сами, честный
итог — **NOT_READY**. Сначала нужен отдельный, прошедший ревью implementation
manifest; менять ядро или строить новый адаптер в этом пакете не требуется.

## 2. Детерминированная среда и закрытое сочетание

Два канала `c=0,1`. Наблюдаемое состояние — координаты `(x,y)` на торе
`Z8 × Z8`, плюс непрозрачный cue ID. Четыре операции имеют непрозрачные ID.
Скрытая от агента перестановка связывает их с `(1,0),(-1,0),(0,1),(0,-1)`.
Операция реально изменяет состояние по модулю 8. Наблюдение содержит цель
`(goal_x,goal_y)`; правильный operation ID, перестановка и остальные исходы
не передаются агенту. Непрозрачный outcome ID совпадает с cue ID достигнутой
координаты. Все четыре операции допустимы, ровно одна достигает цели за шаг.

Генератор специфицирован здесь, но ещё не реализован/запущен. Для любых
целочисленных частей `parts` функция ранга:

```python
sha256(json.dumps(["ac0_confirming_v2", seed, tag, *parts],
                  separators=(",", ":"), ensure_ascii=False).encode("utf-8")).digest()
```

Сортировка по байтам хэша, при совпадении — по целочисленному tuple.
`map,c,index` ранжирует индексы четырёх смещений и назначает их скрытым слотам
`j=0..3`. ID — полный hex хэш с тегами `cue,c,x,y` и `op,c,j`.
Слот `j` — внутренний индекс генератора; в агент не поступает.

**Закрыты пары, где `(x + 2*y + j + c) % 4 < 2`.** Для каждого канала это
128 пар; остальные 128 — training. В каждой точке остаются две неизвестные
операции: нельзя решить тест простым исключением трёх уже наблюдённых.
Training содержит два полных прохода только по открытым парам: 512 реальных
действий на seed. Порядок задаётся рангом `train,pass,c,x,y,j`.
Два повторения — учебные экспозиции, а не независимые подтверждения гипотезы.

Из закрытых пар для каждого `(c,j)` берутся первые 16 по рангу
`closed,c,x,y,j`: всего 128 primary closed задач на seed. Ещё 128 seen задач
берутся аналогично из training с тегом `seen`. Один выбранный случай — одна
попытка действия; повторная разведка на нём не разрешена. Порядок случаев —
`test,phase,c,x,y,j`; порядок меню — `menu,phase,case_index,j`.
`phase` и индексы остаются у evaluator; агент видит только упорядоченные ID.
Одинаковые ID в training/test сохраняют проверку нового сочетания, а не
запоминание нового случайного имени.

Это **перенос комбинаций в заданном семействе**, не новый домен/AC3.
Публичные координаты делают перенос идентифицируемым. Одна лишь смена
opaque ID дала бы невыводимую таблицу, а не содержательную задачу обобщения.
Публичные seeds не обеспечивают криптографической слепоты; отсутствие
передачи seed/слота/перестановки в агента проверяется исходниками и аудитом.

## 4. Одинаковая информация, сильные контроли

Все политики видят одинаковые public поля, учебные реальные transitions и
бюджет действий. Учебная операция принудительна и помечена curriculum;
проверяемый выбор операции начинается на scored задачах. Не выдавать
учебную команду или факт обучения за инициативу ядра.

| Arm | Правило |
|---|---|
| native adaptive | Исполнимую операцию выбирает проверенный путь конкуренции ядра; учится на admitted actual. |
| exact table online | Последний actual для `(channel,cue,operation)`; известное совпадение с целью, иначе uniform среди ещё не наблюдённых действий, иначе среди всех. |
| displacement table online | Последнее выученное `(next-current) mod 8` для `(channel,operation)`; предсказывает результат через modular addition; тот же выбор/tie-break. |
| fixed first | Первая операция в public меню. |
| random uniform | Одна из четырёх; counter-based SHA256 random, без глобального RNG coupling. |
| native frozen posttrain | Точная обученная копия native, дальнейшие persistent updates отключены. |
| native frozen initial | Начальная native модель; curriculum наблюдается, обучение отключено. |

У displacement контроля нет доступа к истинной перестановке: он учит
смещение из actual, но имеет явно указанное структурное предположение.
Он нужен, чтобы преимущество над заведомо буквальной таблицей не стало
ложным преимуществом гетерархии. Аналитический oracle с private labels —
только потолок 100%, без дополнительных агентских попыток.

Случайный tie-break использует rank с тегом `random,arm,phase,case_index,k`,
где `k` — индекс вариата; первые 64 бита трактуются как integer / `2**64`,
действие выбирается через `floor(u * len(candidates))`. Для causal пар arm
заменён общим `causal-pair`; candidates упорядочены по public меню.
UUID и timestamps не участвуют в policy tie-break. Manifest обязан закрыть
все другие источники недетерминизма до confirming.

Native driver кодирует **только** переданные public поля. Конкретное
отображение в `PeripheralToken`/`Feature` и роль контекста должны быть
зафиксированы в implementation manifest и проверены на development.
Не встраивать смещения, ответную таблицу, goal scorer, last-actual mask,
LLM, semantic labels или `select_goal` в периферию. Сравнение исхода с
целью вне ядра допустимо только evaluator и явно названным controls.
Сейчас `Feature.matches` сравнивает вектор, не direction/distance:
наличие координат в payload само по себе не доказывает доступность
пространственной структуры для когнитивного алгоритма.

## 5. Фазы и предельные действия

1. **Training:** 512 общих реальных transitions/seed. Все arms получают
   те же записи; семь копий receipt не являются семью свидетельствами.
2. **Primary:** 128 closed + 128 seen/arm. Каждый случай — из одного и того
   же post-training checkpoint с пустым task context. Actual scored исходы
   остаются только у evaluator; никогда не обучают policies или adaptation.
   Оценка prior transfer не смешивается с online дообучением на тесте.
3. **Adaptation:** в канале0 меняются местами действия слотов0/1, без phase
   flag агенту. Два прохода по первым восьми training парам каждого `(c,j)`
   по рангу `adapt-pair,c,x,y,j`: 128 общих actual. Во втором канале правило
   прежнее. Порядок `adapt,pass,c,x,y,j`. Adaptive arms учатся, frozen — нет.
4. **Post:** те же 128 closed +128 seen coordinate/slot случаев, цели
   пересчитаны по новой среде. Сброс к post-adaptation checkpoint для каждого
   случая; labels не проходят обратно в обучение.
5. **Causal/status:** максимум32 дополнительных реальных действий/seed,
   только native; спецификация ниже. Это отдельная панель, не score transfer.

Основной лимит — **4256 actual world actions/seed, 34048 на все восемь**:
`512 + 128 + 7*(128+128+128+128) + 32`. Oracle не исполняет действия.
Невыполненное действие/abstention — ноль в task success. Uniform fallback
учитывается отдельно и никогда не доказывает полезное использование Gen.
Каждый четвёртый scored случай получает одно нейтральное уведомление из
другого канала перед действием. FIFO transport одинаков для всех; это
механическое перемежение, а не доказательство обученного выбора канала.

## 6. Одна причинная зависимость, с альтернативами

**Условие:** выученный non-atomic Gen доступен живой локальной конкуренции.
**Состояние:** его активное продолжение поддержано текущим cue/context.
**Операция:** ядро, используя этот путь, выбирает operation ID.
**Продолжение:** реальный исход подтверждает соответствующий переход.

До просмотра primary outcomes выбирается один witness на seed: самый ранний
созданный non-atomic Gen с двумя различными реальными curriculum receipt IDs
и явным путём cue → operation → actual. Tie: creation sequence, затем
feature chain; UUID не даёт предпочтения. Task — самый ранний originating
training случай. Нет такого Gen — missing functional evidence; seed не
исключать и не подбирать поздний удобный witness по результату теста.

Четыре пробы из идентичного pre-primary checkpoint, input и random variates:

1. Gen доступен.
2. Sham: блокируется последний по тому же порядку посторонний Gen, не
   участвующий в witness dependencies; если его нет, no-op sham отмечается.
3. Target block: Gen убирается из active context **и** запрещается его
   чтение/повторное раскрытие в исполняемом пути retrieval/competition.
4. Доступность восстановлена из исходного checkpoint.

Это вмешательство должно влиять на policy **до** выбора действия, включая
пути через ссылки; постфактум фильтр forecast/логгера недействителен.
Хэши base/features/evidence неизменны, learning выключен, pending другой
задачи не стирается. Записать реальные обращения к заблокированному носителю
и все альтернативные достаточные пути, включая встроенную цепочку родителя.
Нельзя объявить отсутствие альтернатив лишь потому, что логгер их не вывел:
read path должен быть охвачен проверкой и исходниками intervention hook.

Single-Gen necessity засчитывается, когда available/sham/restored дают
правильное nonfallback действие через witness, а block снимает этот путь
и меняет операцию либо даёт wait/abstain. Если другой Gen сохраняет действие,
это **redundancy**, а не доказанная необходимость и не повод искать другой
удобный witness. Для полного causal критерия требуется не менее6/8 seeds.
Сохранение действия случайным fallback тоже не считается прекращением
операции. Блокировка не создаёт negative evidence.

Это искусственный локальный causal knockout, **не** доказательство
естественного прекращения интереса, исчезновения всех условий или полного
12-звенного цикла. Это утверждение об обусловленности уже философской цели.

## 7. Unknown, отрицание и interruption

На originating witness случае в каждом seed — три парные проверки; каждая
ограничена восемью дополнительными действиями (вместе с четырьмя causal
пробами максимум28, общий cap32). Для всех используются копии pre-primary
checkpoint; состояние после одного случая не обучает другой.

- **Unavailable/unknown:** реальный outcome удерживается на границе доставки.
  У Gen не растёт stop/negative count; pending/ожидание явно сохраняется.
  После доставки исходного receipt он учитывается ровно один раз.
- **Observed divergence:** операция и изменённая среда дают настоящий иной
  outcome; правило меняется только в evaluator. Доставленный actual снижает
  поддержку именно противоречащего ожидания и меняет его ранг/допуск в
  следующей конкуренции. Один `REFUTED` в логе без этого недостаточен.
  Для witness операции вне слотов0/1 evaluator на этой вспомогательной копии
  меняет её местами с первым другим слотом; не фабрикует чужой outcome.
- **Interrupted:** уведомление из канала1-c приостанавливает pending case,
  не увеличивает negative count; после снятия уведомления pending остаётся
  доступным, продолжение возобновляется за <=8 core decision steps.

Требуются все три различения на всех восьми seeds. Если конкретный счётчик
не является действующим causal носителем policy, manifest обязан назвать
реально меняющийся support/ранг, а не подкладывать внешнюю таблицу состояния.
Нет witness/нет различия в поведении — functional criterion failed.

## 8. Пороги и решения до результатов

Primary score — доля достигнутых целей на128 closed случаях каждого seed.
Публикуются восемь парных строк, агрегаты mean и range, seen и post отдельно.
Это восемь репликаций среды, а не тысячи независимых наблюдений.

Абсолютные условия для AC0 candidate: mean native >=0.80, каждый seed >=0.70,
доля **правильных nonfallback** closed действий >=0.80; causal necessity
>=6/8; все status случаи; post closed канала0 >=0.80; падение канала1 <=0.05
от его primary closed mean; весь аудит и ресурсные лимиты соблюдены.

Пусть `d_s = native_closed_s - exact_table_closed_s`:

| Результат | Записанное заранее решение |
|---|---|
| NOT_READY | Нет ревью, manifest или native выбора — confirming не открывать. |
| INVALID/INCOMPLETE | Утечка, неправильный split, испорченный аудит/отсутствующий actual или cap — сохранить провал, не переигрывать автоматически. |
| Лучше: mean(d)>=0.10, d>0 у>=7 seeds | При всех абсолютных условиях — AC0 candidate, требуется независимая репликация; не объявлять gate pass. |
| При этом native ниже displacement table больше чем на0.02 | Простое структурное объяснение сильнее; не заявлять преимущества архитектуры, упростить/пересмотреть механизм. Этот veto имеет приоритет над candidate. |
| Операционное равенство: abs(mean(d))<=0.02 и каждое abs(d)<=0.05 | При наличии trace — только «обусловленная трасса без преимущества»; следующий дизайн — прекращение/предпосылка AC1. AC0 pass не объявлять. |
| Хуже: mean(d)<=-0.10, d<0 у>=7 seeds | Упростить/сменить механизм, не наращивать debug-адаптеры. |
| Прочее/trace failed | Смешанный или недостаточный результат; одно решение ревьюера до нового пакета. |

«Равенство» здесь — заданная инженерная зона, **не статистически доказанная
эквивалентность**. Если native/frozen равны, эффект обучения не установлен;
если native достигает parity с displacement table, всё ещё нельзя приписать
результат особой ёмкости гетерархии. Данные сильного контроля показываются
даже при неудаче native. Одного хорошего seed недостаточно.

## 9. Бюджет, доказательства и хранение

- <=32 core steps/decision; <=8 driver tokens/receipt;
  <=4096 посещённых index records/core step. Считать реальный полный поиск.
- <=16MiB persistent serialized state/arm, включая features, base, context,
  индексы, evidence, очереди и sidecars; peak process RSS <=1GiB отдельно.
- <=180s/seed, <=1800s весь attempt. Слабая машина может дать INCOMPLETE;
  лимит не увеличивать после просмотра качества.
- Raw <=32MiB uncompressed/seed, <=128MiB compressed весь attempt.
  Не повторять full pickle на каждом шаге: checkpoint +полные causal deltas
  и state hashes. Нельзя выбрасывать неудобные события ради cap.
- Raw >1MiB — **вне git**, release asset/архив, URL и SHA256 в отчёте.
  Архив проверяется распаковкой и hashes; коммитить только протокол, код,
  небольшие summaries и md. Это правило не переписывает старые raw PR22.

Каждое событие: run/arm/instance/channel, monotonic seq, causal parents,
public input и доступные операции, actual selected operation, независимый
actual outcome/status, support/Gen delta, query/index work и bytes.
Scored oracle labels хранятся отдельно от agent observations.
Публикация перечисляет все seeds, пропуски, caps, fallback, witness failures,
source/manifest hashes и точные команды. Равные action budgets не означают
равных CPU/RSS; claims экономии требуют отдельных данных.
